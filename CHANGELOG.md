## [Unreleased]

### Added

- **The source of the documentation server is public** (#2260). `server/mcp/` is now part of the public export, so anyone can check the server's privacy statements (it stores nothing and logs no input) against the code. The `/mcp` page links to it; the server's own pages follow with its next deploy.

- **The site has a page `/edih` in English and German for European Digital Innovation Hubs and SMEs** (#2267). It explains a first checked session in one afternoon, names the two default network connections with their switches, and says that live Pi compatibility has not yet been verified in a recorded run. `docs/edih-proof-runs.md` fixes the pass criteria for three recorded Pi runs in advance; none has run yet.
- **The site has English terms of use at `/terms`, and `/edih` names the support reply time for EDIH customers** (#2267). The terms cover the MIT License and statutory rights, the operator and hosting, cookieless measurement and the EU AI Act role of users as deployers. `/edih` and `/de/edih` state that EDIH customers receive a written reply within 3 working days to support requests submitted via GitHub Issues, and link the terms from the page and the footer.

### Fixed

- **Pi tells the model where the plugin lives** (#2277). The extension supplies the absolute package root in the system prompt, and every generated Pi prompt points to its command or skill file under that root. When they are unset, it also sets `CLAUDE_PLUGIN_ROOT` and `PI_PLUGIN_ROOT` to that root and `SO_PLATFORM=pi` in the Pi process, so `${CLAUDE_PLUGIN_ROOT}` calls in skills run from Pi's bash tool, and the scripts they start still use the `.pi/` state directory; every child process of Pi inherits these values.
- **The shell MCP server returns the same JSON-RPC errors as the Node transport** (#2275). Malformed JSON gets `-32700`, invalid requests get `-32600`, and valid notifications receive no reply. The shell launcher now hands every line to the Node server, so Node is required to start it, as it already was for the plugin.
- **Security-delta reports each check's duration in whole milliseconds** (#2275). The result contract rounds fractional durations after validation.
- **`/security posture` reports a migration hint for a pnpm 12+ pin with only `onlyBuiltDependencies`** (#2275). The check passes because pnpm 12.21.0 blocked unapproved builds with that configuration.
- **The MCP starter and plugin resolver prefer the highest cached `x.y.z` version** (#2275), ignoring a build suffix such as Codex's `+codex.<timestamp>`. Modification time breaks ties and orders copies without a release version.
- **`/security status` shows the reason for a skipped advisory pulse, and security events reach the repository ledger from subdirectories** (#2211). Commands run inside a linked worktree use the main checkout's ledger.
- **The axe pre-check waits for finite animations to finish** (#2190). It uses the latest expected finish time, up to 10 seconds, so a 2.5-second page animation can complete before the accessibility scan.
- **`countSkillInvocationsBySession` warns on its first call** (#1852). The warning directs callers to `countSkillInvocationsAcrossFiles` in `scripts/lib/session-close-backfill.mjs`.
- **Both MCP stdio transports reject `id: null` with `-32600 Invalid Request` and leave notifications without a reply** (#2274), including notifications for unknown methods.
- **Security-delta keeps network checks on the performance clock when a custom timer is supplied** (#2274). The runtime-floor check falls back to its default budget for a non-finite deadline, and network duration is reported in whole milliseconds.
- **`/security posture` checks mirror protection only for recognized GitHub hosts and accepts pnpm's `allowBuilds` map** (#2211). A pnpm 12+ pin with only the legacy `onlyBuiltDependencies` setting now reports the migration fix.
- **The MCP server answers `ping` and marks failed tool calls with `isError: true`** (#2272), in both the Node transport (Claude Code) and the shell transport (Codex, Cursor). MCP 2024-11-05 requires an empty result for `ping`; 5.22.0 answered "Method not found". A tool call outside a git repository or a failed read now comes back as a tool result with `isError: true` instead of plain text or a JSON-RPC protocol error.
- **Bounded ledger and transcript reads retain the first complete record** (#2268) when the window starts immediately after a newline.
- **STATE.md flow arrays accept apostrophes inside unquoted values** (#2268) without swallowing the following entries.
- **Gitleaks scan budgets and security-delta check durations use a monotonic clock** (#2268) so wall-clock changes cannot distort them.
- **Security-delta network deadlines use a monotonic clock** (#2270) so wall-clock jumps can no longer shorten or extend network checks.
- **The 37 skill command sites that used the shell fallback now use plain `${CLAUDE_PLUGIN_ROOT}`** (#2258, slices 1–3). Claude Code left the fallback intact, so Bash ran `node "/scripts/x.mjs"` and failed to find the module. The skill header explains how to resolve the absolute path when the token remains literal. When `/close` runs in the plugin repo, the mirror uses that checkout's export code. Plugin paths formerly written with `$PLUGIN_ROOT` or `${PLUGIN_ROOT}` and bare calls to shipped scripts now use `${CLAUDE_PLUGIN_ROOT}` too. The linter reports unsubstituted forms and missing skill headers, including paths in skill references. The hook-development lesson is exempt from the header rule because its examples teach hook manifest paths.

### Changed

- **The install guide documents headless bootstrap permissions, and the security skill explains manual review on Cursor and Pi** (#2275, #2205). The bootstrap measurement covers `claude -p --plugin-dir` only.

## [5.22.0] - 2026-11-24

`/security` gives one read-only entry for repository security work, and `/bootstrap` measures the repo before it asks. Hooks no longer start `node`, `git` or other tools from inside the project. The confidential-names list covers GitLab group names, telemetry sends only from interactive Claude Code sessions, the lock reaper no longer deletes the lock of a live session, and gate and check durations can no longer be negative. A read-only documentation server for the OpenAI plugin directory comes with its own package variant.

### Added

- **STATE.md keeps a files-touched ledger and records abandoned approaches** (#868, #867). Wave close appends the verified changed paths to a deduplicated `files-touched` list that resume and planning read; a re-plan or a discarded wave records what was tried, why it was dropped and which files it touched, through the existing What Not To Retry writer.

- **`/bootstrap` measures the repo before it asks** (#2230). `scripts/setup-precheck.mjs` reports git, VCS, package manager and the test, typecheck and lint commands, each as detected or not found with the reason (no remote, no `package.json`, no lockfile, missing script). It composes the existing detectors, writes nothing and never assumes npm. `/bootstrap` shows the status before the tier question. An absent or `none` command still falls back to the npm default in the gate; a later cut changes that.

- **`/security` gives one read-only entry for repository security work** (#2201, #2202, #2203, #2204, #2205). Four modes: `status` (which security mechanisms run), `deps` (lockfile advisories ranked fix now, can wait or not reachable), `posture` (install and publish settings) and `agent-setup` (what steers the agent in the repo and on the host). `/security review` routes to the existing `security-reviewer` agent. The CLI `scripts/security.mjs` only reads; `scripts/security-emit.mjs` records one counts-only event `orchestrator.security.command`.

- **The confidential-names list also covers GitLab group names, and takes an extra list of your own** (#2251). `confidential-names.mjs generate` now adds the segments of each project's group path, except ordinary words for how a code host is organised (`products`, `internal`, `infrastructure` and others in `GENERIC_GROUP_SEGMENTS`), which match widely in a public tree and protect nothing; `--no-groups` leaves groups out. A new `confidential-names-extra.json` beside the exception file (or `--extra <path>`) adds names that are not in GitLab, such as customer or product names from your own notes; the exception file still wins. Output stays counts only.

- **A generated, host-local list of confidential names for the leakage scanner, required where a repo publishes** (#2238). `node scripts/confidential-names.mjs generate` reads the project names of the GitLab projects you are a member of (GET only, paged; any missing page or zero projects aborts without writing), subtracts a hand-kept exception file, and writes the list with mode 0600 beside `owner.yaml`; it prints counts only, never a name. The public export (`--public-export`) and the release check in a `mirror: curated` repo now fail closed without a usable list; an explicit empty list stays allowed but is reported as "CP11 deliberately off". Other repos and plugin users without a list are unaffected; pre-commit only hints. Setup: [docs/confidential-names-list.md](docs/confidential-names-list.md).

- **The OpenAI skills package carries its listing details and an icon** (#1931). `scripts/export-openai-skills.mjs` now writes display name, subtitle, long description, category, starter prompts and the four listing URLs under `extensions["com.openai"].interface` and ships `assets/icon.svg` as logo; the OpenAI plugin portal requires these before a submission. `--check` allows that one file under `assets/` and refuses an icon that is a symlink, is not an SVG, or carries a plain `<script>` element or event handler, a logo that names a file the package lacks, and a listing without its required fields.

- **A read-only documentation server for the OpenAI plugin directory, and a package variant that names it** (#2260). OpenAI's portal no longer takes skills-only plugins; the open path needs a public MCP server. `server/mcp/` is one: dependency-free, stateless Streamable HTTP, five read-only tools (`search`, `fetch`, `list_skills`, `check_session_config`, `get_release_notes`) that answer from the public documentation of the released version. It stores nothing and logs no input. `node scripts/export-openai-skills.mjs --with-mcp` builds the package with a root `mcp.json` for exactly this server, five positive and three negative review cases and release notes; the check refuses any other MCP configuration. The skills-only build is unchanged. Hooks stay outside the directory, so the full plugin is still installed from GitHub or npm. See `docs/distribution/openai-remote-mcp.md`.

- **The site has a page `/mcp` for the documentation server** (#2261). It shows how to add the server to your agent, the five tools and what the server stores (nothing); the home page, the guide, both llms texts and the README point to it.

### Changed

- **`countSkillInvocationsBySession` is deprecated** (#1852). It has no caller; use `countSkillInvocationsAcrossFiles` from `scripts/lib/session-close-backfill.mjs`. The export stays for at least one minor cycle.
- **New bootstraps ignore the three hook logs** (#2246). `.orchestrator/metrics/events.jsonl`, `subagents.jsonl` and `skill-invocations.jsonl` are written on every hook call but committed by nothing, so a user's `git status` stayed dirty after every session. The bootstrap's ignore block (also run by `--upgrade` and `--refresh-lock`) now lists these three exact paths; `sessions.jsonl`, `learnings.jsonl`, `eval.jsonl` and the other ledgers stay versioned, and files Git already tracks stay tracked.

- **`release.mjs --reconcile` on the trusted route exits by the install job** (#2229). A confirmed npm receipt exited 0 with `ok: true` even when the public install job failed or was never measured. It now exits 0 only when the job passed, 1 when it failed and 3 when it was not measured; the version stays `published` and `installState` names the case in `--json`.

### Security

- **Hooks no longer start `node`, `git` or other tools from inside the project** (#2237). The Node shim skipped only relative PATH entries, so a project that put its own directory on `PATH` (direnv, mise, a settings `env` block) could supply the `node` every hook ran, and hooks started `git`, `ps`, `gh` and similar tools by name. The shim and a shared lookup now skip the project directory, the working directory, every `node_modules` entry and PATH entries that are not fully qualified, and resolve each tool once to an absolute file. Entries below the project are skipped too, except when the project is the home directory, an ancestor of it or a filesystem root, so a session started there still finds user-installed tools. A census test fails when a module the hooks load starts a bare program name.

### Fixed

- **Wave supervision proves tail-sourced stagnation end to end, and a restart reads a bounded window** (#1154). The tailer CLI writes a real `stagnation_detected` record with `source: "tail"`; on restart it reads at most the last 1 MiB of the events file instead of the whole ledger.
- **Gate durations can no longer be negative** (#2266). `duration_seconds` of the full and incremental gates, the navigator record and the process-group run time were wall-clock differences; a clock step on a WSL VM reported -1. They are measured on a monotonic clock now, and the `ms` of the security-delta checks is clamped at 0 (a negative value made the check throw).
- **The session-start banner also names a still-running run behind a canceled pipeline that has a failed job** (#1852). That case returned `phase: canceled` and said only "no verdict"; the general case was already covered.
- **The agent cap counts a just-resumed agent** (#2056). After a resume the harness marks the agent as running again only after a short delay; until then the cap skipped it, so one start could exceed the cap. A finished marker is now checked against the agent's own transcript when that was written after the marker, within 10 seconds.
- **The lock reaper no longer deletes the lock of a live session** (#2127). After a killed hook left `session.lock.write.acquire` behind, every heartbeat failed silently, the lock timed out and another session reaped it. The reaper now re-checks the lock under the same write guard as every other writer and keeps it while the guard is held. A guard file older than two seconds is reported once per hook with both file names and the event `orchestrator.session.lock.stale_acquire_guard`.
- **The staging fence reads long shell commands in linear time** (#2190). 90 kB of shell words took 8 to 13 seconds, past the 5-second hook budget, and the record was lost; it now takes about 0.1 s. It also records `git add` after a written-out `\n` in piped shell data.
- **The scope guard keeps a subagent's real trailer id** (#2190). A `[Subagent hand-back]` line inside a report was read as the frame and dropped the id.
- **The pre-push gate names `SO_GATE_HOSTS` also when the gate host returned no report** (#2190).
- **An agent's wave is no longer lost to a stale manifest, and `wave: 0` never reaches an event** (#2222). For the wave label of agent events, a manifest bound to this session now wins over an unbound one left by another harness (`.codex/` before `.claude/`), so those fields stay filled; the scope guards keep treating an unbound manifest as the deciding, enforcing one; the event envelope takes a manifest wave only when it is a positive integer. `scripts/session-tree.mjs` filters to the requested session while it reads the ledgers instead of holding every line (max RSS about 200 → about 100 MB on a 41 MB copy of a real ledger, byte-identical output).
- **The release drift check reads the whole version in `site/llms.txt` and `site/llms-full.txt`** (#2259). It read only `X.Y.Z`, so `5.21.1-rc.1` or `5.21.1.2` there passed as `5.21.1`; `--set-version` now also replaces such a suffix.
- **`site-deploy` tells a damaged stage receipt from a missing one** (#2235). Promote still refuses both, but an unreadable receipt is no longer reported as "no stage receipt". The help says that a stage receipt never expires, so an older stage build stays promotable as the way back, and that the receipt is not a security boundary.
- **The vidlab marketing scripts no longer send an empty key or show it in the process list** (#2242). `lab.sh` (all three providers) and `img.sh` stop with a message naming the variable or file when the key is missing or empty, `img.sh` passes the bearer header through a file descriptor like `lab.sh` and ends non-zero when the image request fails instead of leaving an empty PNG, key file paths are resolved before the scripts change directory, and `imgs.sh` stops at the first failed image.
- **The release acceptance counts only the install run of the released commit** (#2229). It took the newest Actions run for the tag without reading its commit or trigger, so a green run on another commit could count. It now requires a `push` run whose `headSha` is the tagged commit; without one the job is not measured.
- **The live-site check compares the whole version** (#2229). `5.21.1-rc.1` or `5.21.1.2` on the site passed as `5.21.1`.
- **`release.mjs --help` states the install-check wait from the code** (#2229). It said 15 minutes while the release waits 25.
- **`directory-preflight` and the MCP file check no longer report success for what they did not check** (#2229). An empty listing in `strict` mode is now a blocking finding, an unparsable MCP file is reported apart from a missing one, `--mode off` reports `checked: false` instead of `files: 0`, a `strict` pass names the holds that still block a listing, and a Codex or Cursor MCP file without any server fails the JSON check. `/repo-audit` no longer expects the removed root `.mcp.json`.
- **`paths.confidential-names-file` accepts a path starting with `~/`** (#2251). The list counted as missing, and every pre-commit run in a publishing repo blocked.
- **Skill steps call plugin scripts through the plugin root** (#2188). Eleven `emit-event.mjs` calls in `/close`, `/evolve` and `/memory-cleanup` and five other plugin-script calls used `node scripts/…`, which does not exist in a user's repository. They now use the plugin-root form the other skill steps already use. That form needs the plugin root resolved first (`skills/_shared/config-reading.md`); Claude Code's Bash tool does not set `CLAUDE_PLUGIN_ROOT` itself, so this is not yet proof that the events arrive in a user's repository.
- **`SECURITY.md` names all three commands the destructive guard denies before loading a policy** (#2249): PowerShell tool calls, command lines past the size bound, and a here-doc left open by its substitution. It named only the last. It also said an internal error in the hook allows the command; since #1671 that command is denied, and only a failed module load still lets commands through, with a warning.
- **Telemetry sends only from interactive Claude Code sessions** (#2255, #2256). CI markers, SDK or missing entrypoints, and Codex, Cursor or pi harness markers suppress the flush, its daily fallback and the consent question, even with saved consent, `SO_TELEMETRY=1` or fleet mode. Codex, Cursor and pi sessions send nothing until an interactive marker is measured for them.
- **The destructive guard checks the whole command for a here-doc left open by a substitution before evaluating policy rules** (#2249). A quote in the body can hide later commands from the lexer. The denial keeps its existing reason and event ID.
- **The curated GitHub export prints the scanner's CP11 opt-out warning on stderr** (#2251). An explicitly empty confidential-names list remains a valid publishing choice, and the operator sees the warning even when the scan passes.
- **The destructive guard no longer reads a here-doc left open by its command substitution as data** (#2249). In `x=$(cat <<E )` the substitution closes before the body; bash then reads the following lines as the here-doc body, zsh runs them as commands. The guard followed bash, so a reset on the next line passed. Such a line is now denied as an unmeasurable command; the bootstrap's here-docs, which close inside their substitution, stay allowed.
- **Gate tests no longer fail on a slow host** (#2247, #2245). The security-delta tests gave every check the 2-second network budget, which also covered the fixture's git reads; they now pass an explicit deadline unless they test the deadline itself. The destructive-guard checkout tests measure a 'path not measurable' deny again up to three times through one shared helper, never retry a content deny, and log the first reason.
- **The install guide no longer reports the headless telemetry prompt as current** (#1872 was fixed in 5.16.0), and `docs/telemetry.md` names the SDK entrypoint gate.
- **A first bootstrap in an empty repository is no longer denied by the plugin's own guard** (#2246). The destructive guard read a quoted here-doc body inside `$( … )` as shell words and took `{ repoRoot: …, minimal: true }` for a brace expansion, so every documented `RULES=$(node --input-type=module <<'NODE' … NODE)` step of `/bootstrap` (five in the skill files) was denied as an unmeasurable command, reported under `git-checkout-discard`. Here-doc bodies are now skipped during brace expansion as bash does; stdin shells in a substitution (`$(bash <<E …)`, `cat <<E | sh`) are judged as before. An unmeasurable-command deny now says so instead of advising a path reset. The bootstrap writes the instruction file with the file tool or `>>`, never `> CLAUDE.md`, and the generated hard-rules block is English without internal references (the old German heading is still recognised).
- **The public install check waits for the tarball, not only for the version** (#2212). After 5.21.2 was published the registry answered `npm view` for the new version while its tarball could not yet be downloaded (still a 404 6.5 minutes after the publish), so the install step failed right after the wait step had succeeded. `scripts/wait-for-npm-version.mjs` now also requires HTTP 200 on the registry's own `dist.tarball` URL, within the same deadline, and names in its timeout message which of the two was missing. The workflow allows 900 seconds for it.
- **`SECURITY.md` no longer fails the release drift sweep** (#2239). Its "Fixed in" sections name the version they describe, which the sweep read as a forgotten version bump at the next release.
- **`release.mjs --reconcile` prints `installable not measured` when the install job was never measured** (#2212). It printed `installable no`. The `installable` field is unchanged; the exit codes of the trusted route changed with #2229 (see Changed).
- **ADR 0018 states who lifts the push block of the `github` remote** (#2212). It said the release tail and `/close` do. Both only check the push URL and refuse while the block is set; lifting it is a manual step per push.
- **The public texts name both default network connections** (#2228). README, the guide (text and FAQ data), both llms texts and `docs/telemetry.md` said the plugin only asks npm for updates. By default it also runs the security check (Node release index, CISA KEV feed, lockfile package names and versions to OSV, `gh` for GitHub remotes). All surfaces now name both connections and their off switches, telemetry stays consent-only, and `tests/docs/network-claims-parity.test.mjs` reads the switch names from the code and pins every surface against them.
- **Windows is labelled best effort** (#2236). `docs/install.md` called native Windows supported. macOS and Linux are checked before every release; Windows runs and has a native smoke test in CI, but there is no native acceptance before each release, and reported bugs get fixed. README, the start page, the guide and the llms texts say the same, and the bug report template asks for harness, version, native shell and install path.
- **The install guide names the Lead add-on's real command and marketplace.** `docs/install.md` said `navigator --help` and `owner-inbox@navigator-mods`; lead-session-orchestrator 0.5.0 ships the command `lso` and the marketplace `lead-session-orchestrator`.
- **`SECURITY.md` covers opening a repository you did not write** (#2226). Since 5.21.2 the post-edit hooks run no command from a foreign project's Session Config ([GHSA-f4r8-fcrq-2pj3](https://github.com/Kanevry/session-orchestrator/security/advisories/GHSA-f4r8-fcrq-2pj3)); the section names what still runs in `/session` waves and gates, and the command-trust passage no longer equates the editor hooks with `package.json` scripts.
- **`tests/lib/reconcile/vault-links.test.mjs` names its precondition** (#2241). On a host whose temp directory chain is writable by group or others the owner policy fails closed and the test failed with an unrelated `ENOENT`. It now fails with a message that names the directory.

## [5.21.2] - 2026-11-22

The post-edit hooks run a typecheck, ESLint or an import check only in the plugin's own checkout. The session film left the plugin for a Vercel Blob store, the changelog is split by age, and `scripts/session-tree.mjs` shows which agent ran in which wave.

### Changed

- **`typecheck-command` is no longer run by the post-edit hook**; the quality gate still runs it (#2226).
- **The session film no longer ships with the plugin** (#2217). The two film files, 34 MB together, left the repository and the public mirror; a plugin installation from GitHub no longer downloads them. The site serves them from a Vercel Blob store through a same-origin rewrite, so `/guide` plays the film from the same paths as before and the browser contacts no other host. The curated snapshot shrinks from 57.4 MiB to 24.6 MiB.
- **The changelog is split by age** (#2219). `CHANGELOG.md` keeps the current minor versions (5.19.0 and newer); older sections moved unchanged into six files under `docs/changelog/`, listed in the footer. Every file stays under the 256 KiB the Claude plugin directory scanner reads for a text file, and a test fails when one grows past it or a version appears twice. The release tooling reads only the newest section and is unchanged.

### Added

- **`scripts/site-deploy.mjs` deploys the website with the Vercel CLI from a clean export of one commit** (#2219). The file set has its own source of truth, `site-deploy.json` (`site/` and `vercel.json` minus the design studies and campaign files); the export is checked file by file and may hold no env file. Modes: `plan` (default, deploys nothing), `preview`, `stage` (a production build without domains) and `promote`, the only step that moves the domains. This prepares taking the website out of the public plugin mirror; until that switch the site still deploys from the mirror.
- **The README logo loads from `docs/img/`** (#2219), and a test checks that every image the README loads from the mirror by raw URL is a tracked, exported file.
- **Subagent records name the wave they ran in, and `scripts/session-tree.mjs` prints the tree Session → Wave → Agent** (#2218). `subagents.jsonl` start and stop rows and `orchestrator.agent.stopped` carry `wave` and `wave_role` when the session's own wave-scope manifest names them; before, no subagent row and 19 of 558 stop events did. The reader takes a raw session id or a semantic label, lists agents without a known wave under `unassigned` instead of dropping them, and reports in `coverage` how many agents carried a wave. A source it could not measure prints as `n/a` with a warning on stderr, never as 0, and the set of resolved session ids does not depend on the order of ledger rows. Rows written before this change carry no wave. Exit codes: 1 input error, 2 unreadable ledger.
- **`scripts/directory-preflight.mjs` reports what the Claude plugin directory scan objects to, before the export** (#2216). It measures the curated snapshot of a commit: file count against 512, text files over 256 KiB, binaries the validator does not inspect, an MCP server declared in `.mcp.json` and inline, line-ending rules without `eol=lf`, and a lockfile beside `package.json`. The mode is a ladder: `off`, `warn` (default, report only) and `strict` (exit 3 on a blocking finding). Holds never fail a run, because a reviewer decides them. The release skill names the step and the scan readback after each mirror push.

### Fixed

- **The post-edit hooks start a typecheck, ESLint or an import check only in the plugin's own checkout and skip in every other project** (#2226).
- **Comments, skill descriptions, reference docs and changelog entries no longer name consumer repositories** (#2225).
- **`scripts/site-deploy.mjs --mode promote` moves the domains only to a deployment this checkout staged** (#2219). A `--mode stage` run records its URL, source commit and project in `.orchestrator/runtime/site-deploy/`; promote refuses any other URL and refuses `--source`, which it used to ignore. The deployment URL is read only from whole tokens of the Vercel output, so `https://x.vercel.app.example/…` is no longer cut down to `https://x.vercel.app`.
- **`orchestrator.wave.completed` and `wave_dispatch.scope_materialized` keep their session ids when the session lock lives in another checkout** (#2218). Both emitters looked for the lock in one directory only. The batch hook now reads the root that holds the session's own lock, and the materialize CLI falls back to the process's own lock within the same repository.

## [5.21.1] - 2026-11-22

The MCP server is declared once per harness: the root `.mcp.json` that repeated the Claude Code declaration, and that the Claude plugin directory scan refused, is gone from the tree. The trusted release route now measures the public install check to its end.

### Fixed

- **The MCP server is declared once per harness** (#824). The root `.mcp.json` moved to `mcp/servers.json`, and the Codex and Cursor manifests point at it. Claude Code keeps the inline declaration in `.claude-plugin/plugin.json`; it used to load the root file as well, and the Anthropic directory scan refused the repeated server name on every version. The launch command is byte-identical, so the plugin root still never comes from the client's working directory. Codex and Cursor installs pick the new path up on reinstall or update. The native Windows setup now rewrites `mcp/servers.json` and keeps its backup beside it. On a Git clone whose `.mcp.json` was edited by hand, the update stops with Git's "local changes would be overwritten" message: restore the file with `git checkout -- .mcp.json`, delete a leftover `.mcp.json.before-windows-setup`, update, then run the Windows setup again.
- **A trusted release with an unmeasured public install check exits 3** (#2215, #2212). The release command retries transient GitHub CLI errors for up to 25 minutes and records the job result in the release proof. Exit 3 means the version is published and only the install result is outstanding. ### Security

- **Behaviour change: `allow-destructive-ops: true` in the Session Config no longer relaxes the destructive-command guard** (#2089, reported privately by dviolante). The agent being guarded could write that line itself, and the deny message advertised it. `hooks/pre-bash-destructive-guard.mjs` now ignores the key and prints a stderr warning; the config parser still accepts it, and it does nothing. - **The vault-mirror auto-commit commits every unstaged mirror artifact, whichever run wrote it** (#2089, reported privately by dviolante): it selects each path under `40-learnings/` and `50-sessions/` that has an unstaged working-tree change, carries the generator marker and that nobody has staged, and commits those with `git commit --only`. A mirror file left unstaged by another session's run is included. Gitleaks scans the selected files; when gitleaks is missing and the vault uses it, nothing is committed. A failed add or commit unstages only the selected paths, also in a repository without a first commit; a rollback that itself fails is reported as `rollback: "failed"` in the result line. They read the text of a tool call, so a script file a call runs is not inspected, not every alias spelling of a protected path is recognised, and on Codex text typed into an already open interactive shell reaches no hook. ### Changed
