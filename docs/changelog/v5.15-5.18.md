## [5.18.0] - 2026-11-11

### Added

- **session-start lays native liveness over the peer banner** (#1052): on Claude Code the coordinator calls `ListAgents` once in Phase 0.5 and marks each registry peer `busy`/`idle` and reachable by `SendMessage`, joined through `~/.claude/sessions/*.json` on the session id the host registry also keys on, never on `cwd` (two peers in one working copy share it) or a name prefix. Display only; harnesses without the tool print that liveness is not available.
- **Lead-guided runs for grill, ux-grill, deepen, test-audit and discovery** (#1976): a session that nobody answers — lead-guided by a fleet coordinator, or headless (`claude -p`, `codex exec`) — no longer stalls or skips these skills. `skills/_shared/lead-guided-mode.md` names the four detection signals, the three duties (take the own recommendation, park owner-class questions, record one `Entscheidung (autonom, Lead-geführt): …` line per answer) and the owner classes (external effect incl. a public tracker, money, accounts, deletion, security, critical product decision). grill runs a "Selbst-Grill" that answers only with cited evidence; deepen executes the rewrite and names the original as the rejected option; ux-grill, test-audit and discovery take their recommended dispositions; a lead-guided run ends with a report whose open points are statements, never a question. Interactive behaviour is unchanged. grill and deepen carry the text themselves so the OpenAI skills-only export stays self-contained (export check: 0 violations). Measured with headless probes on 2026-11-08: deepen and ux-grill made 0 `AskUserQuestion` calls, wrote their decision lines and ran to the end.
- **Viewport pair per page and `/test --target-kind`** (#1962): the playwright-driver capture recipe writes `ax-snapshots/<page-slug>-w1440|w390.yaml` plus screenshots for every page (rubric-v2 convention, `locator.ariaSnapshot()`) and a `visited-urls.json` with the URL actually driven per page and viewport. `/test --target-kind live|production-build|dev-server --target-url <url>` requests a kind; `LIVE RUN` / `PRODUCTION-BUILD RUN` is granted only when the visited URLs have the target's origin, otherwise the report says dev-server and names the mismatch. `checkReportComplete` receives routes, never slugs; the evaluator is the single source of the report header line.
- **`/plan new` applies the research budget with a fixed time limit** (#1922): each research agent checks a 4-minute wall-clock limit itself, because `/plan` waits in the foreground and the coordinator cannot stop a running agent; the call limits of the `/plan` budget stay. Headless and autonomous runs cannot raise the limits, every research prompt carries them, and PRD Section 2 gets a "Research Budget" subsection with allowed and used calls per agent. `skills/plan/mode-new.md` is the third place that states the `cross-repos` rule, and the test holds all three equal. A headless `/plan new` run under the budget is not yet measured, so #1922 stays open.
- **`/evolve` reads owner decisions** (lead-session-orchestrator#948): `evolve.extra-sources` accepts `kind: owner-decisions` and turns a recurring deviation pattern from the export into an `owner-preference` candidate, only above the thresholds in `skills/evolve/references/evolve-analyze-mode.md`. The candidate passes the same confirmation as every learning, and such a learning never grants an approval.
- **Agent caps are enforced, not just written down** (#1959): the new PreToolUse hook `pre-agent-cap.mjs` on `Agent` counts this session's running agents (subagent sidecars minus finished ones, plus same-message dispatches claimed under a lock), classifies them as reading or process-starting from the agent's tool list, and denies a dispatch above the cap from the accepted Auflagen file, else the Standard-Auflagen (2 + 2) once `fallback_due_at` has passed; without fleet integration there is no cap. Below 15 % free memory (released above 20 %) no new process-starting agent starts; unmeasurable memory says „nicht messbar“ and keeps the file cap. It only blocks starts, never kills, and fails open on its own errors.
  - The transcript is read only when the count can change the verdict (#1965): an engaged brake denies a process-starting dispatch before any read, so a slow parse under memory pressure can no longer run into the 5 s hook timeout (which lets the dispatch through), and the "below the cap" shortcut counts only the dispatch's own class. A dispatch from a subagent counts like the coordinator's: nested agents land in the same `subagents/` dir (16 of 4734 subagent transcripts in 14 days started agents, every nested sidecar was there, measured 2026-11-06), so the cap counts the whole agent tree of a session. A nested agent is released by its terminal notification in the main transcript (44 of 45 in 14 days; the rest still waits for the 30-min TTL); this also frees its file scope in `pre-task-scope-disjoint`.
- **Context threshold for every session** (#1960): `post-tool-context-threshold.mjs` (PostToolUse) reads the last main-chain assistant line of the session's own transcript and adds one hint at 700k („Übergabe-Datei vorbereiten, keine neue Welle mehr beginnen“) and one at 800k („am nächsten MR-Schnitt übergeben“). Session Config `context-threshold:` (`enabled`, `prepare-k`, `handover-k`; defaults true/700/800). Subagent tool calls never spend the hint; an unmeasurable context writes no marker. The fleet check-in accepts an optional `kontext_k`.
- **ux-evaluator rubric-v2: a person's judgment before the counters** (#1961): six human checks per page and viewport (five-second, primary-action, dead-or-locked, empty-state, density, decoration) run before the mechanical checks, which stay only as a footnote and never as the overall verdict. A report without human-check verdicts for every page × {1440, 390} is incomplete (`BLOCKED`); the target is labelled live / production-build / dev-server. `scripts/lib/test-runner/human-checks.mjs` gives a deterministic floor from the AX snapshot (placeholder areas, dead or locked controls, competing actions). `/test` takes the rubric from the profile: web-gate uses v2, the mac profiles keep v1.
- **Issue balance per session** (#1947): session-end prints „Issues dieser Session: +N angelegt, −M geschlossen, Saldo …“ with population and measurement time (`scripts/issue-balance.mjs`); anything unmeasured reads „nicht messbar“, never 0. LOW findings that get filed go into the session's one `[Backlog-Sammel]` collector; MEDIUM and above stay single issues.
- **„Entscheidungen für dich“ and „Nicht geprüft“** (#1950): mandatory sections (up to five points, „keine“ allowed) in the close report and the handover template; plan tasks may name an „Erwartung“ the report compares against.

- **The Stop notification is a per-user switch** (#1936): `owner.yaml` `notifications.stop: false` (or env `SO_STOP_NOTIFICATION=off`) stops `on-stop` from sending the desktop notification (OSC 9 + OSC 777, "Session stopped — your turn"). The rest of the Stop path runs unchanged; before, the only way out was disabling the whole hook. Default stays on. `on`/`off`/`1`/`0` are accepted as well as booleans, because YAML reads a bare `off` as a string. Measured 2026-11-03: with 10+ parallel sessions in Ghostty, which renders both sequences, every Stop raised two banners. Documented in `docs/owner-config-schema.md` and `scripts/lib/owner-config.example.yaml`.
- **Pre-push reuses a Full Gate receipt for the pushed tree** (#1897, SO side of N4): before every route, `.husky/pre-push` runs `run-quality-gate.mjs --receipt-check --pushed-sha <sha>` in its temp clone, a read-only probe that passes the push on a green receipt for exactly this clean commit tree (exit 0) and otherwise exits 10 without running, emitting or writing anything, so the remote, partial and full routes run unchanged.
  - Only `context: 'pushed-tree'` records count: the hook's local fallback mints them with the new write-only `--receipt-record` (always runs the suite, never reads the store or navigator, writes only on a clean tree whose store is another checkout), the remote router after a verified green run (with the gate host's alias and Node). A Quality-wave or session-end receipt from the working copy never answers pre-push.
  - The key neutralises Node (`gateDefinitionAnyNode`), because the router already accepts any gate host and the hosts differ (measured 2026-11-03: m5 v26.13.0, win-wsl v24.21.0, M4 v24.22.1); the Quality wave and session-end keep the full definition. The store is the real repo's (`--ledger-root`); the partial gate and the mirror smoke never read or write receipts, and pre-push never touches navigator.
  - A hit carries `reused_from: {tree, at, host, key: 'any-node'}`, and every hook-run Full Gate event carries `pushed_sha`. Applies to `main` and tags too; CI stays authoritative. The hook feature-detects `--receipt-record` in the pushed tree's runner, so an older commit keeps the old invocation. Measured before: 195 of 200 Full Gate runs since 2026-10-20 were pre-push runs, 9 re-ran a tree already green within 12 h, 0 reused a receipt.

- **Trusted publishing (ADR-0018 route B) is built, opt-in** (#1906): `release.mjs --publish --trusted` pushes the tag and the curated snapshot to GitHub, where `.github/workflows/publish.yml` publishes with provenance after the owner approves the run in the GitHub environment `npm-publish`; no npm token is involved. The workflow runs on a pushed tag `v*` only, and its `guard` job ends the run without publishing when the version is already on npm. `scripts/lib/release-trusted.mjs` verifies the receipt from public registry data (trusted-publisher marker, provenance workflow, ref, commit and tarball digest, per-file content comparison); `--reconcile` and `--resume-tail` use it for a trusted proof, and `release --check --trusted` reports the trusted-publisher evidence in the `publish-route` row (a plain `--check` shows only whether the workflow is armed). The receipt also requires the downloaded tarball's sha512 to equal `dist.integrity`; under `mirror: curated`, `--resume-tail` and `--reconcile` check the snapshot commit's `Source-Commit:` trailer before pushing the GitHub tag or confirming a receipt. Without approval in time the script ends `awaiting-workflow` (exit 1); approve, then `--resume-tail`. The default `--publish` stays route C. Pending: the owner's Trusted Publisher setup on npmjs.com, the first rehearsal and the later default switch.
- **Codex `SessionEnd` is wired** (#1919): `hooks/hooks-codex.json` registers `on-session-end.mjs` for `SessionEnd` with the upstream maximum `timeout: 3`; `SessionEnd` is native and required in `scripts/lib/codex/plugin-contract.mjs` and `check-hooks-symmetry`; under `SO_PLATFORM=codex` the telemetry flush is capped at 700 ms so the hook stays under the 3 s cap. Measured live twice on codex-cli 0.160.1 (2026-11-02, plugin installed from the branch into a throwaway `CODEX_HOME`): the hook fired, released the lock on its own (the model turn ended in a 401, so Stop never ran) and left no registry entry; the second run raised no peer question (#1874 point 2). `Interrupt` stays unwired and unmeasured.

- **The Full Gate receipt also lives in the navigator gate-run ledger** (#1897): on a clean tree (the content tree equals `HEAD^{tree}`), `run-quality-gate.mjs --variant full-gate --receipt` reads the navigator ledger as gate `so:full-gate` when the SO-local store has no receipt, and writes every real run there with `quelle: so`.

  - A reuse from the ledger is visible as `reused_from: {tree, at, source: 'navigator', entry_sha256}`. A dirty tree never reaches the ledger.

### Security

- **The guards read stdin redirects on compound statements, `0<<<` and `cat < <(…)`** (#2014): forms older than 5.18.0 ran a blocked `git reset --hard` past the destructive guard (and a ledger write past the sessions-ledger guard, which shares the pipe reading). A stdin redirect behind a group, subshell, `if` or `while` (`{ xargs -n 2 git; } <<< '…'`, in bash a discard without any MULTIOS) now feeds the statements of its body, also where a `cat` there writes into the next pipe; a pipe into a compound (`echo … | if true; then xargs -n 2 git; fi`) feeds every statement of its body, not only the condition; `0<<<` is read as a here-string (the `0` was an argv word), and stdin sources stay fd-agnostic as before: a here-string, here-doc or `< <(…)` on any fd counts, with or without a dup; and `cat`, `tee` and line filters hand on `< <(…)`. Ceilings (ADR-0017): values assigned by `read`, and `sh -c` positionals filled from the argv after the string, stay unread.
- **The guards read xargs data that zsh joins across sources or that an empty expansion shifts** (#2012): two forms ran a blocked `git reset --hard` past the destructive guard (and a ledger write, an unrecorded `git add` or an `apply_patch` past the other three readers of the shared pipe reading), both older than 5.18.0. Under zsh, MULTIOS joins a pipe and a here-string or heredoc into one stream (`echo reset | xargs -n 2 git <<< '--hard'` runs `git reset --hard`); that joined stream is now read as one more reading beside the bash one, also through `cat`/`tee` in the chain. In zsh and bash, an item that expands to nothing at run time (`echo w0 w1 reset $X --hard | xargs -n 2 git` with an empty `X`) shifts the real batches; the windows are now also read with every subset of non-literal items removed, and a line with more than four such items under batching is denied fail-closed. Census before the fix: 0 of 4651 real commands join a pipe with a here-string, 2 combine batching with one non-literal item; the replay gives the same verdicts as before. Ceilings (ADR-0017, follow-up #2014): a name that only the joined stream spells is still unread by the ledger and apply_patch prefilters, and stdin sources on a compound statement, an explicit `0<<<` on the xargs path, `cat < <(…)` without a pipe and a non-literal argv word that shifts `sh -c` positionals are read only within one segment or not at all — all older than this fix.
- **The destructive guard reads GNU `-d` escapes of any length** (#2011): GNU findutils reads an octal or hex `-d` escape with any number of digits (measured with GNU xargs 4.9.0: `-d '\0054'` and `-d '\x02c'` split at `,`), while the guard read such data as one item, so a comma-separated reset ran unread. Escapes are now decoded the same way up to 255; a value the guard cannot decode (over 255, `\x` alone, the lenient `\x0x2c` / `\x+2c` forms) makes the reading unreadable and the line is denied.
- **The destructive guard reads more xargs forms, and the xargs window alignment is withdrawn** (#2003 points 1-3, #2006): newly read and denied are data run by a wrapper without a program (`echo '…' | xargs env`, also `nice`, `nohup`, `timeout 9`, `command`, `stdbuf -o0`, `sudo`), a shell without a fixed `-c` (`printf '%s\n' -c '…' | xargs -d '\n' sh`, each window read as the shell's argv), and items split at a single-character `-d X`. Unread pipe data counts only when no rule matches the rest of the line, and its deny names the pipe read budget instead of the first rule asked (`git-reset-hard`). The aligned reading of `-n`/`-L` windows that !382 shipped for #2006 is withdrawn: four review rounds each found a form the guard denied before and let through after, which really ran a discard (a run-time expansion such as `$X` or a glob, a zsh `word(N)` qualifier, a redefined `echo`, and zsh MULTIOS joining a pipe with a here-string or heredoc at xargs). Every window is read from every start index again, so short path lists under `-n`/`-L` stay denied fail-closed, now with the pipe-budget reason; #2006 is reopened for an approach that does not rebuild xargs' split. A replay of 4651 real commands gives the same verdicts as before.
- **The apply_patch guard reads data piped into a shell and the zsh/ksh option grammar** (#2003 points 4-5): `printf 'apply_patch …' | sh`, a here-string and `… | xargs -0 sh -c` passed `hooks/codex-apply-patch-guard.mjs`, which unlike the ledger guard and the staging fence did not use the blocker's `pipedShellData`; data it marks unreadable is denied. `zsh -cO 'P' x` and `ksh -copipefail 'P'` are read with their own grammar, as `dashCPayloads` reads them, beside the bash reading. Ceiling: data from a file or a variable stays unread.
- **A path reset built from a payload names its real reason** (#2003 point 6): a reset read from xargs data, a `-c` string or `eval` is still denied, now as "built by xargs or a shell payload, its directory is not measured" instead of "unreadable directory". A spent pipe or xargs read budget is named as such (#2006), not as a brace expansion.
- **The destructive guard reads xargs data the way xargs runs it** (#1999): 26 forms that ran a blocked `git checkout -f`, `git reset --hard` or `git clean -fdx` over a changed file passed the guard; all 26 are now denied, and a replay of 4651 real commands gives the same verdicts as before.
  - **`-I` fan-out no longer times out.** `printf '<3000 lines>' | xargs -I{} sh -c '{}…(1000×)'; git checkout -f other` took 5.7 s, past the 5 s hook timeout, which Claude Code treats as non-blocking (allowed). The substituted length is now charged to the line's read budget before the string is built, and exhaustion is the existing fail-closed deny (under 0.1 s).
  - **Data that does not come from a pipe is read**: here-strings, here-docs, `< <(…)`, `-a <(…)` and `--arg-file=<(…)`.
  - **Abbreviated GNU long options are resolved** (`--rep=@`, `--max-arg 1`); an unknown or ambiguous option makes the reading unreadable (denied) instead of dropping it.
  - **Data under a `-c` string is always judged**, so `for a; do eval "$a"; done` and `eval "${!#}"` no longer hide it.
  - **The `-c` string is judged with `"$@"`, `$*` and `$N` substituted**, so `echo --hard | xargs sh -c 'git reset "$@"' _` is read as the reset it runs.
  - **`-n`, `-L` and `-s` batches are read from every item index**, so a batch that starts mid-data is judged. Every window costs budget before it is built, duplicates included, and repeated batch options count once, so a flood fails closed instead of running past the hook timeout.
  - **BSD `-J`, and `-L`/`-n` given after `-I`, append the items**, and that data is judged too.
  - **`xargs su|runuser|sg|xargs|git` builds the argv xargs would run**, e.g. `echo checkout -f other | xargs git`.
  - **Named ceilings:** other programs behind xargs (`xargs rm`), `-a file` / `< file` data, `-d X` items, GNU's `-L` blank continuation, and `${1:-x}` / `${@:2}` / `shift` substitution stay unread (the data itself is still judged under `-c`).

The record-only fence records `git add` behind them. Ceiling: `echo b.txt | xargs git add` is not recorded.

### Changed

- **The destructive guard reads words the shell still expands, and zsh's precommand modifiers** (#1892). Before, each of these let the whole command through, rule included:
  - An option word with an expansion counts as a possible `-r` and `-f` and passes no path exception, because it may split off a path (`rm -rf${x} /data`, `rm "-rf$x" /data`, `rm -rf${x} node_modules`).
  - An rm word that reads `rm` once empty expansions drop counts as `rm` (`r${x}m`, `rm$(true)`, `rm${${x:-}:+}`).
  - `builtin`, `noglob`, `nocorrect` and zsh's `-` are unwrapped like `command`, so `builtin eval "…"`, `- bash -c '…'` and `noglob git clean -fdx` are judged by their payload or subcommand.
  - Named limit: a bare variable (`rm -f "$T"`) could carry `-rf` too, but 437 real rm commands in 7 days carry one, so it stays a plain operand. So does an expansion that is not empty (`$R` holding `rm`).

- **The destructive guard reads an empty expansion inside a word** (#1893): with `x` unset, bash runs `git res${x}et --hard` as `git reset --hard`, and every git rule (reset, push --force, clean -f) allowed it. Each command is now also judged as it reads with empty expansions: `$name`, `${…}`, `$((…))`, `$( … )` and backticks read as empty, `${x:-w}` as `w`, and a match in either reading counts. An unknown ref before `--` stays unjudged as before (`git checkout $REF -- f`). A default word nested deeper than 8 levels counts as a match (fail closed). Measured on 145,960 real Bash commands from 7 days against 13 rules: 0 verdict changes, mean cost per command 0.36 → 0.50 ms.

- **`$"…"` strings and `$"…"`/`$'…'` here-doc delimiters are read as bash runs them** (#1895): bash without a message catalog drops the `$` of `$"…"`, so `git reset $"--hard"` and `git push $"--force"` ran while the guard read `$--hard` and allowed them. The pattern rules now take the bash reading; path resolution keeps zsh's, so `> $"PWD"/f` stays unresolved. A here-doc delimited by `<<$"EOF"` or `<<$'E\x4fF'` (escapes decoded) now ends where bash ends it, so the lines after it are judged as commands instead of body text.

- **so-hud reads a data command's quoted pattern as text** (#1891): `grep -E "denied|git push|deny" …` asked for a push, because the `|` inside the quoted pattern split off `git push` as a command of its own. A segment cut out of a quoted word of a data command (grep, rg, echo, …) now counts as text, unless `eval` parses the word again or the output is piped into a command that runs it (`| sh`).

- **Project cleanup exceptions cannot traverse escaping symlinks** (#1886). `rm -rf` now checks the real filesystem location under `node_modules`, `.orchestrator/tmp` and the state-directory `filescopes`, including a trailing `/` or `/.`.
  - Removing a bare symlink stays allowed. A resolution error blocks the exception.
  - A target the shell still resolves no longer passes any exception, `/tmp` included. That covers a `..` segment (rm follows it through a link), `$`, a backtick, a zsh `(`, and a glob or brace in a directory segment (`node_modules/*/`).
  - A glob in the final segment (`node_modules/*`) stays allowed.
  - A relative target is judged where the shell runs it: from the hook payload's `cwd` and every literal `cd` on the line. The `cd` target is added as a candidate rather than replacing the old directory, because a failed `cd` leaves the shell in place. A `cd` with `..`, a subshell, a substitution, `pushd`/`popd`, `eval` or `source` make the directory unknown.
  - A `cd` behind `builtin` or a zsh precommand modifier (`noglob`, `nocorrect`, `-`) counts, and so does zsh `chdir`. A bare `cd` or `cd ~` is unknown when the line may set HOME. A relative `cd` is unknown when the line or the environment may set CDPATH.
  - `$TMPDIR` is expanded only in the first command of the line, only when TMPDIR is set, and only when no other word of that command expands something: zsh expands words left to right, so `rm -rf -v${${TMPDIR::=/usr}:+} $TMPDIR/lib` deleted `/usr/lib`. There is no `os.tmpdir()` fallback any more. A trailing `/` on a `/tmp` target follows the link, as in the project branch.
  - Replay of 801 real recursive-rm commands from 7 days: 797 verdicts unchanged. Of the 4 new denials, 3 cost a real command: twice `$TMPDIR` after another command, once `cd "$P"`. The fourth was a review probe. The third review's fixes changed none of 785 replayed verdicts.
