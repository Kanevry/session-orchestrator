- **`node scripts/release.mjs --resume-tail --target X.Y.Z` finishes an interrupted publish tail in one command** (#1791). It first runs the read-only registry check and refuses on an integrity mismatch, then tags the commit recorded in the release proof (an existing tag must point at it; on `mirror: curated` the GitHub tag's snapshot must carry `Source-Commit:` of that commit), pushes missing tags, creates the GitHub release, checks the live site and runs `--reconcile`. A second run changes nothing, and it never publishes. Every push, fetch and `ls-remote` of the tail runs in its own process group with a 900 s deadline and prints its PID; after the deadline the whole group is killed and survivors are named. Contract change for deep importers: the exported `tagAndPush()` of `scripts/release.mjs` now returns a Promise (it shipped synchronous in 5.13.0).
- **`node scripts/migrate-rule-envelope.mjs --root <repo> [--apply]` moves old rule copies to the visible envelope** (#1792). The caller checks the fleet boundary before passing a root.

- **The destructive-command guard refuses a worktree removal that would lose state** (#1789): a new typed rule `worktree-remove-unsafe` denies every forced `git worktree remove` and a plain one whose target still holds gitignored session or fleet state (`.orchestrator/runtime/fleet/**`, `STATE.md` under `.claude/`, `.codex/`, `.cursor/`, `.pi/` or `.orchestrator/`, a top-level `.orchestrator/*.lock`). An operand that is not a path is resolved the way git resolves it (a worktree's unique trailing path component); a target the guard cannot measure is denied, one git cannot find stays allowed. Quoted words, abbreviations of `--force` (`--forc`) and calls inside `$( … )`, `bash -c` or `eval` are judged too; `python -c`, `node -e`, `xargs`, script files, a `-c` payload held in a variable and a few rarer shell spellings are a named ceiling (#1797). The policy now holds 14 blocking rules. session-end Phase 4a and `/memory-cleanup` hand the forced removal to the operator's own terminal.
- **A secret value in Bash output is reported the moment it appears** (#1786, SEC-008): `hooks/post-bash-write-verify.mjs` scans every Bash result (`stdout`/`stderr`, or a string on Codex) for values of qualifying env keys of the hook process, raw and JSON-escaped, using the masker's own needle rules (new additive export `secretNeedleEntries` in `scripts/lib/secret-masker.mjs`). A hit emits `orchestrator.security.secret_emitted` with key names and counts only, never a value, plus one `systemMessage` asking for rotation and an owner-queue item. Measured over 44,382 Bash results of 896 transcripts: 0 of 8 hits false, 0.05 firings per 1000 Bash calls, about 0.05 ms per call. Values a command loads itself (`set -a; . ./.env.local`) stay invisible; on Cursor only the event is written. A shape-based variant over `.gitleaks.toml` was measured at 88.9 % false alarms and is not built.
- **Session start reports known security problems without a network request, probe 21 `security-pulse`** (#1769, stage 2): it reads a host-private cache and warns when the running Node is below the security floor of its major, when the lockfile findings cached for HEAD include a malicious package or a critical vulnerability (KEV-listed ones counted through their CVE aliases), or, with `security-delta.mode` not `off`, when the last real close (backfilled records skipped) wrote no `orchestrator.security.delta` event of its own session. An absent, incomplete or stale cache gives no banner and is reported as `not-measured`, `degraded` or `stale`, never as clean; it starts the detached refresher `scripts/security-pulse-refresh.mjs` (one atomic claim per repo per 10 minutes, allowlisted child environment, TTL 6 h, incomplete parts retried after 30 minutes; `SO_SECURITY_PULSE_REFRESH=off` disables it). Lockfile names and versions reach the banner only in a strict charset. Security-Delta findings now carry the CVE aliases of the fetched OSV records in `ids`.
- **Session start shows the fleet boundary from the navigator's conditions file word for word** (#1809): `node scripts/fleet-auflagen.mjs <session_id> --render` prints, after the unchanged JSON line, the `grenze` field of an accepted conditions file under one header line, byte for byte (new pure helper `renderAuflagenNotice()` in `scripts/lib/fleet-protocol.mjs`). A `grenze` with a control character other than tab and newline, a bidi, zero-width or line-separator character, a BOM or an invisible tag character (U+E0000–U+E007F) is withheld with one notice line, and under `--render` the JSON line writes those characters as `\uXXXX` escapes, so none reaches the terminal raw; without `--render` the output is unchanged. An absent or rejected file prints nothing extra. Phase 7.6 calls `--render` and carries the block verbatim into subagent prompts that search across repos.
- **Session start reports dead links in the memory index** (#1801): `readDreamSignals()` in `scripts/lib/auto-dream.mjs` counts `[text](target)` links in `MEMORY.md` whose target is not an existing file, line by line in linear time (`<…>` targets and `"…"`, `'…'`, `(…)` titles read; schemes, pure anchors, `[[wiki]]` links and links inside inline code skipped; targets outside the memory folder are never `stat`ed; lines over 4096 characters skipped; `null` when there is no `MEMORY.md`, never 0). The new export `listDeadIndexLinks()` gives the same list to `/memory-cleanup`, whose new first step and final check call it instead of a GNU-only `grep -oP`. The maintenance-due banner adds `memory: <N> tote Index-Links — /memory-cleanup` when N > 0, also when nothing else is due or the housekeeping cooldown runs, without changing when auto-dream is due. Measured 2026-10-26 06:43 UTC on the development host (`readDreamSignals()` over every `~/.claude/projects/*/memory/MEMORY.md`): 0 of 38 memory folders would show the line today (an earlier cleanup removed 96 dead links), so it appears only when links are lost again.

### Fixed

- **A curated mirror snapshot can be pushed through the pre-push hook again** (#1836, release blocker for 5.14.0): for a push to the `github` remote whose commit carries a `Source-Commit:` trailer, whose source commit has an `include` export policy and whose tree defines `test:mirror`, `.husky/pre-push` runs `npm run test:mirror` (what GitHub CI runs) instead of the full quality gate, which was red by construction on the slim tree (no `vitest.config.mjs`, no `tests/`, but `mods/so-hud/tests/*.test.ts`; measured on snapshot dcc2d84311ee). Every other push keeps the full gate; a red or missing `test:mirror` still blocks.
- **The worktree-removal guard measures big clean worktrees instead of refusing them** (#1826). `hooks/pre-bash-destructive-guard.mjs` read `git status --ignored` with Node's default 1 MiB output limit, so a clean worktree with `node_modules` (1.3–6.1 MB of status output, measured 2026-10-26) hit ENOBUFS and every `git worktree remove` of it was denied as "not measurable": 11 of 16 approved removals that day. All four git reads in the hook now allow 64 MiB. A status above that limit and a timeout still deny, and a valuable ignored file inside a big tree is still named and blocked.
- **security-delta no longer takes `.npmrc` `minimum-release-age` as a release-age gate under pnpm 11 and later** (#1822). pnpm 12 ignores policy keys in `.npmrc` without a warning (measured: pnpm 12.15.0 installed a 19 h old package that pnpm 10.34.5 refused), so the check read green where nothing protected the install. The nearest `packageManager` pin, searched from the lockfile's directory up to the repo root, now decides: only an exact `pnpm@X.Y.Z` below 11 lets the `.npmrc` key count, and any range or partial pin is read as possibly 11 or later. `pnpm-workspace.yaml` `minimumReleaseAge` counts on every version. Without a pin the old reading stays, as a named ceiling.
- **security-delta keeps the package names of a private Python index away from OSV even when the index is set outside the requirements file** (#1772). An index set in an `-r`/`-c` include, by an including file, in `PIP_INDEX_URL`, `PIP_EXTRA_INDEX_URL` or `PIP_FIND_LINKS`, or in a pip.conf that pip reads now keeps the file's pins private. Includes are followed in both directions over the tracked requirements files: cycle-safe, depth 8, at most 256 files. Lines are split the way pip splits them. Option lines follow an allow-list, so an unknown option such as `--no-index`, a `${VAR}` value, a symlinked or unreadable include, or an unreadable pip.conf makes the pins unverifiable. Such pins are counted as unchecked (`pip-index-unverifiable`), so the run reads degraded instead of clean. Stored index URLs lose their userinfo. The remaining named ceilings are tracked in #1827.
- **A retained peer-card section keeps the indentation of its first item** (#1816, follow-up #1813). `mergeDerivedBody()` and the managed-section write-back both trimmed the content, so `  - old` became `- old`, and a code child indented under it changed its value. Both now drop only leading blank lines and trailing whitespace, and a rerun stays byte-identical.
- **Two tests no longer depend on the host they run on** (#1673, #1823). The so-hud "linear time" cases time eight small runs as one sample against one big run, so a 4 ms tick clock (WSL2) and host preemption hit both sides alike. Before, a small run under 4 ms read 0, and the growth ratio became the big run's duration in ms. Quadratic code is still caught (a quadratic mutation read 47 against the bound 32). The `isPidAlive` test uses PID 2^31−1 instead of 2,000,000, which WSL2 can assign. It also asserts that the ESRCH path is the one taken.
- **`marketing/vidlab/lab.sh` no longer puts the API key into curl's arguments** and gives the Authorization header only to OpenRouter URLs under `https://openrouter.ai/api/v1/videos/` (#1818). `heroloop.sh` reports a failed measurement with its reason and cleans up its temporary directory (#1819). The GitLab test shards install zsh, so the vidlab cases run on Linux instead of being skipped (#1821).

- **security-pulse and the Security-Delta no longer flag a version outside an advisory's known affected range** (#1814): OSV keeps some GHSA ranges open-ended (`introduced: 0.0.0`) and carries the real bound only in `affected[].database_specific.last_known_affected_version_range`, so `sandbox@4.4.0` was reported critical for two advisories that end at `< 1.0.0`. `scripts/lib/security-delta/osv.mjs` now drops an advisory only when every matching `affected` entry has a parseable bound (`<`, `<=`, `>`, `>=`, `=`, comma-joined) that excludes the installed version, compared segment by segment with a missing segment read as 0 (`1.0` equals `1.0.0`). A missing detail record, a missing or unparseable bound, a pre-release installed version and an entry that carries its own `fixed`, `last_affected` or `limit` event or a `versions` list keep the finding (fail-closed).
- **A retained list followed by an appended indented block now merges the same way twice** (#1813 F2): `mergeDerivedBody()` in `scripts/lib/peer-cards/merger.mjs` writes an empty HTML comment between a kept list item and an appended indented unit (the separator CommonMark names for a list before an indented block), so the next run no longer reads the block as the item's child and appends a second copy. The block's bytes are unchanged.
- **`/guide` names the canonical Person as author and publisher in its JSON-LD** (#1815): the TechArticle references the home page's Person node by `@id` (no Person copy on the page). The owner-leakage check (CP7) exempts on `/guide` exactly the two `author`/`publisher` lines carrying that `@id`, nothing else on the page; the #1237 guard forbids the author domain outside the guide's JSON-LD and pins it inside to exactly those two `@id`s; `tests/site/seo-graph.test.mjs` exempts only that Person `@id` from local resolution, every other id must still resolve on the page.
- **Dialectic apply retains existing points omitted from a proposed section.** `mergeDerivedBody` compares list items (with their nested children), paragraphs and ATX headings whitespace-normalised and fenced code line by line, keeps existing content and appends new units when any are missing, and reports `omitted-items-retained` with the retained items; a section whose existing content holds an unclosed fence is left unchanged and reported as `unterminated-fence`. A complete proposal still replaces the section; only operator-confirmed section names in `confirmDrops` allow omissions to delete points. One measured apply would otherwise have deleted 13 existing points; reworded points stay alongside their originals until confirmed (#1810).

- **A session record keeps its native id and token rollup when the session works outside its start checkout** (#1773): 12 of 44 ledger records since 2026-10-15 had no `raw_session_id` and therefore no token totals, because `emit-session` trusted only the cwd's `current-session.json` — absent in a linked worktree (4 records), overwritten by a later session (7) or relabelled after a compact (1). When that marker proves nothing, the process's own session id is adopted if `events.jsonl` shows exactly that id carrying the record's label; a label the process never carried stays unstamped.
- **A replica host no longer reports the dialectic as due when the git-shared peer cards are current** (#1777): the cadence is measured from the later of `.orchestrator/dialectic-last-run` (host-local) and the newest valid peer-card `updated`; `readDialecticSignals` reports the deciding source as `lastRunSource`.
- **The site's Person entity no longer lists its own URL in `sameAs`** (#1771), on the English and the German home page; a seo-graph test fails whenever a node repeats its `url` there.
- **The shell lexer reads zsh clobber redirects and stays linear on function floods** (#1795, #1731): `>!`, `>>|`, `>>!`, `>&|`, `>&!`, `&>|` and `&>!` now name their write target in the scope, STATE.md and sessions-ledger guards (before: no target, or `!`). A flood of 10,000 `f() {` took 2,204 ms in `tokenizeCommand` and could outlast the 5 s hook timeout; it now takes 7 ms. The delete-target reader sees zsh's `time repeat N`, short `if`/`while` bodies after `[[ ]]` or `(( ))`, `coproc NAME { … }` and `time -p --`, so `while [[ -n x ]] { rm -f .orchestrator/metrics/events.jsonl }` is denied. Word tokens carry per-part quoting, so `$PWD/` and `~/` targets expand exactly where the shell expands them.
- **The hookless-worktree guard also judges merge, rebase and am** (#1736): a train merge, rebase or `git am` in a linked worktree without its hooks directory used to skip `pre-merge-commit`, `commit-msg` and the applypatch hooks silently. Forms that run no hook (`--abort`, `--quit`, `--show-current-patch`) and explicit skips stay allowed, `commit --dry-run` is no longer blocked, and `env -C` / `--chdir` is followed.
- **check-rules catches a forged envelope line spelled with any non-ASCII look-alike** (#1796): small capitals (U+1D07 read as `e`) and letters from blocks no table listed passed check (f). Every non-ASCII letter, digit or symbol now stands in for any token letter.
- **The scope and STATE.md guards see more Bash write forms** (#1793): `echo x &> f`, `&>> f`, `>& f`, `>>& f` and `"$PWD/f"` / `~/f` now name their target. `$PWD/` is expanded only when the shell's value is provable (not after `cd`, `pushd`, `popd`, `PWD=`, `source` or `eval`, not with a single quote or backslash in the command), `~/` only unquoted; an unprovable value stays unknown, never a wrong path. zsh clobber forms and per-part quoting are #1795.
- **Security-Delta never sends private npm package names to OSV because of the working tree or the host config** (#1788): the registry policy comes from `.npmrc` at the checked revision, read like npm reads it (quoted keys included); a registry set in `npm_config_*` or the user npmrc counts as private, and a user npmrc that is not a regular file (FIFO, device, directory) degrades instead of blocking or reading as public. A TypeError while reading a lockfile now ends as `internal-error`, not `unparsed`.
- **check-rules rejects look-alike and duplicated untrusted-content envelopes** (#1792): check (f) normalises full-width, Cyrillic/Greek look-alikes, combining marks and invisible characters before matching, and requires exactly one start line before exactly one end line. Small capitals are #1796. `guard-design.md` now expires on its earliest live absorbed date, 2026-11-04.

### Security

- **The destructive guard reads the zsh brace-group forms it missed** (#1707): zsh runs several forms the shared reader `scripts/lib/command-blocker.mjs` did not see as deletes or truncations, so the guard allowed them on protected paths:
  - a `}` glued to the last word (`{rm -r .orchestrator}`, `{echo x >CLAUDE.md}`), now judged with and without the brace;
  - a quoted or doubled glued opener (`{"unlink" P;}`, `{'unlink' P;}`, `{{unlink P;}}`);
  - the bodies of `repeat <n>`, `always`, `time`, `coproc` and the `f() cmd` short function. After a glued or one-word close (`x}`, `{true}`) an `always` is read both ways: zsh starts a new statement there, bash passes `always` and every word behind it to the command, so `{ rm -f x} always CLAUDE.md; }` still counts CLAUDE.md as a target.

  A quoted single-word verb (`"unlink" P`) is no longer skipped by the delete collector either; on its own it was a bypass. All changes can only add targets.
- **so-hud reads the push configuration and closes push-gate bypasses** (#1569): before a push runs without a question, so-hud reads `push.*`, `remote.<r>.push`, `remote.<r>.mirror`, `remote.pushDefault`, `branch.<b>.pushRemote` and `submodule.recurse`; anything but `push.default` unset or `simple` (or `current` for a named branch) and `push.autoSetupRemote` asks, as do a push refspec, a mirror, a push remote that points elsewhere and submodule recursion. The remote must be defined in git config (`remote.<r>.url`); a legacy `.git/remotes` remote asks. Closed: lowercase `head` (git reads it as `HEAD` on a case-insensitive filesystem); an apostrophe in a heredoc and a line break inside quotes hiding a background `&`; git calls inside `$(…)`, backticks and `<(…)`, and `git-<name>` run by path; a `cd` in a subshell, background job, pipeline or `||` branch (the folder is now unknown and the push asks); `git -c` with other keys on an earlier git call; an input redirection in front of the command (`</dev/null git push origin main` was not held); variable assignments on the line before a push, which now ask unless the name is harmless (a single lowercase letter, `rc`, `out`, `msg`, `sha`, `ref`, `head`, `base`, `branch`, `res`, `ok`, `tmp`, or an uppercase letter with at most one more uppercase letter or digit such as `D`, `WT`, `TZ`) — `HOME`, `PATH`, `XDG_*`, `GIT_*`, `SKIP_PRE_PUSH` and `source` ask; an earlier `fetch` with any option or a `::` word, and an earlier `log`, `show` or `diff` with an option that writes a file or runs a program (`--output`, `--ext-diff`, `--textconv`; on `fetch` `--upload-pack`, also abbreviated); a command that is not git before a push that names its branch (`printf … >> .git/config; git push origin feat/x`); an output redirection before any push, on an allowed git step, `cd`, an assignment or `exec` (`git log --format=… >> .git/config`, `cd . > .git/HEAD`, `exec 3>>.git/config`); and a hook fired by an earlier `add`, `commit`, `status`, `fetch` or `checkout -- <paths>`, which now makes a push ask unless so-hud measured that no hook can run — hooks defined in git config (`hook.<name>.command`) count, and such a step in another folder than the push's (`git -C ../b commit -m x && git push origin feat/x`, `cd ../b && git commit -m x && cd ../a && git push …`) always asks. The scanners run in linear time; a 50,000-character line no longer takes seconds. Receipts and beacons are written only into real directories owned by the user and appended only to a regular file with one link (symlinks and hard links are refused); without `O_NOFOLLOW` (native Windows) an `lstat` check stands in, with a race between check and `chmod`; removing a beacon follows no symlink.
