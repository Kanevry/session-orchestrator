Which command helps me right now?

Pick what you want to do. Each command below says when to use it, what you get, how to type it and what happens next.

I want to …

  • Clarify an idea/brainstorm, /grill, /deepen
  • Start a project/bootstrap, /plan new
  • Plan a feature/plan feature
  • Build/session, /go, /close
  • Maintain/session housekeeping

  • Test/test, /ux-grill

Rule of thumb

Which session to start
Do you know exactly what to build?/session feature
Not sure what to build yet?/plan feature first
Big or unclear change?/session deep
Tidy up?/session housekeeping

How to type a command in your coding tool

How each coding tool runs a command
Claude CodeType /name in the chat. In headless claude -p, use the long form, for example /session-orchestrator:session deep.
Codex CLIPick the skill in the Codex chat: $session-orchestrator:name. It is not a shell command. Plain /go and /close do not work there, and Codex never starts go or close on its own.
Cursor IDEType /name. Agents run one after another.
PiType /name. Each command is a prompt template.

Start here

Six commands are enough for your first sessions. Learn these and ignore the rest until you need them.

/bootstrap Start here

When
You use session-orchestrator in a repo for the first time.
You get
A CLAUDE.md (AGENTS.md on Codex and Pi) with a Session Config and the minimum repo structure, committed. You see the created files and the commit hash.
Type it
Claude Code
/bootstrap [--upgrade <tier>]
Codex
$session-orchestrator:bootstrap
Cursor
/bootstrap
Pi
/bootstrap
Touches
Commits asks you first 7 to 9 setup questions; /bootstrap --fast --no-interview skips them and uses sensible defaults
Needs
A git repository.
Then
Run /session feature for your first session.

Source: skills/bootstrap/SKILL.md

/session Start here

When
You sit down to work on a repo and want to know what to do next.
You get
It reads your repository (git state, issues, CI, environment) and proposes what to work on. Nothing changes until you agree.
Modes
  • housekeeping tidy up and maintain
  • feature build one clear feature (best for a first session)
  • deep big or unclear change: look first, then build (the default)
  • ultradeep an optional, longer profile of deep for a named research question; not a fourth type
Type it
Claude Code
/session [housekeeping|feature|deep|ultradeep] [task]
Codex
$session-orchestrator:session deep
Cursor
/session deep
Pi
/session
Touches
Changes files asks you first only session state (STATE.md, session lock); code waits for /go
Needs
/bootstrap done. With no session history, a bare /session first asks you for task and mode.
Then
Agree to the plan with /go.

Source: commands/session.md

Claude Code

Codex

Cursor
/plan feature
Pi
/plan
Touches
Opens issues asks you first writes the PRD or retro; new also creates a repo and commits
Needs
/bootstrap done. /plan new uses plan-baseline-path when configured, else the bundled templates; feature and retro never need it.

Only an idea: /brainstorm. Scope known: /plan feature. Exactly clear: /session feature. The PRD lands in docs/prd/ by default (plan-prd-location).
Then
Optionally /grill the PRD, then /session feature to build it.
