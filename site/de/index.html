01 / Was es ist

Liest zuerst, fragt, und arbeitet dann in geprüften Schritten.

Session Orchestrator ist ein kostenloser Zusatz für KI-Werkzeuge, die Code schreiben, zum Beispiel Claude Code. Für alle, die schon eine KI programmieren lassen und vorher den Plan sehen wollen. Open Source, eine Zeile zum Installieren.

02 / So funktioniert es

Was es macht, in einfachen Worten

Die meisten KI-Werkzeuge tippen los, bevor sie überhaupt geschaut haben, was da liegt. So entsteht die Reparatur am falschen Fehler, oder zwei Helfer ändern gleichzeitig dieselbe Datei.

Es liest zuerst.

Bevor irgendetwas geändert wird, liest es deinen Projektordner: was zuletzt gemacht wurde, was offen ist, was kaputt ist. Danach sagt es dir, was es gefunden hat.

Du stimmst den Plan ab.

Es schlägt vor, was angefasst wird und was nicht. Du sagst passt, oder du änderst es. Vorher fängt nichts an.

Die Arbeit wird in fünf Teile zerlegt.

Die Arbeit wird in fünf Schritte geteilt: lesen, bauen, feilen, prüfen, abschließen. Jeder Schritt hat seinen eigenen Helfer und eine kurze Liste der Dateien, die er anfassen darf.

Nach jedem Schritt eine Prüfung.

Nach jedem Schritt läuft eine automatische Prüfung. Geht sie schief, startet der nächste Schritt nicht. Bitten hilft nix. Überspringen geht nicht, das ist gar nicht eingebaut.

Was bleibt, wenn die Session vorbei ist.

Eine schriftliche Notiz, was gemacht wurde und was nicht, dazu Hinweise für das nächste Mal. Still dazugelernt wird nichts.

04 / Installieren

Wähl dein Werkzeug

Dasselbe Plugin, vier Wege zur Installation.

Claude Code

Plugin-Marketplace

/plugin marketplace add Kanevry/session-orchestrator

/plugin install session-orchestrator@kanevry

Danach einmal npm install im Plugin-Cache laufen lassen und Claude Code neu starten.

Bekannt kaputt. Die Zeile, die bis 2026-08-19 für diesen Schritt dokumentiert war, funktioniert nicht: claude plugin dir ist kein Unterbefehl von Claude Code, der Aufruf endet mit 1, und den Ausweichpfad, den er dann genommen hat, gibt es nicht. Der Ersatz darunter löst den Pfad stattdessen aus dem Plugin-Cache auf und wurde auf einer echten Installation durchgehend getestet.

cd "$(dirname "$(find ~/.claude/plugins/cache -name package.json -path '*session-orchestrator*' | head -1)")" && npm install

Codex CLI

Klonen und Installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/codex-install.mjs

Liest AGENTS.md statt CLAUDE.md.

Keine Durchsetzung der Schreibgrenze. Der Hook für den File-Scope läuft auf dieser Umgebung nicht. Die fünf Schritte und die Prüfungen funktionieren; die Schreibgrenze ist hier eine Vereinbarung, kein Mechanismus.

Cursor IDE

Klonen und Installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/cursor-install.mjs /absolute/path/to/your/project

Pfad nötig. Der Projektpfad ist Pflicht. Ohne ihn meldet der Installer fälschlich Erfolg.

Pi

Paketmanager

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

pi install npm:session-orchestrator

Dieser Weg installiert seine Abhängigkeiten selbst; die anderen drei brauchen einmal npm install.

05 / Für Entwickler

Fünf Schritte, eine Prüfung dazwischen

Der Schreibbereich wird pro Schritt (wave) vorab deklariert, und die Quality-Prüfung (gate) lässt sich nicht überspringen.

Fünf Schritte: wer sie ausführt, was sie schreiben dürfen, wie viele Dateien, und die Prüfung danach
SchrittWer macht esDarf schreibenDateienPrüfung danach
W1 Discovery nur lesende Explorer nichts 0 Befunde belegt
W2 Impl-Core Code-, DB-, UI-Implementierer Kern des Features 12 inkrementelle Prüfung
W3 Impl-Polish Fix- und Integrations-Agenten Fehlerbehebungen, Randfälle 5 inkrementelle Prüfung
W4 Quality Vereinfacher, Test-Autor, lesendes Panel nur Tests 8 volle Prüfung, nicht überspringbar
W5 Finalization 1 bis 2 Agenten SSOT, Issue-Aufräumen 2 Abschluss-Review

Die Dateizahlen sind die deklarierten Schreibbereiche (file scope) einer Session, keine feste Quote. Ein Schritt deklariert seinen Bereich, bevor er läuft; die Zahlen ändern sich pro Session, die Regel nicht.

08 / Fragen

Fragen, die Leute stellen

Ist das selbst ein Werkzeug, das Code schreibt?

Nein. Es ist ein Zusatz, der ein vorhandenes Code-Werkzeug ordnet. Den Code schreibt weiterhin das Werkzeug; hier wird festgelegt, was es zuerst liest, was es anfassen darf, und wann es stehenbleiben und sich prüfen lassen muss.

Mit welchen Werkzeugen läuft es?

Mit Claude Code vollständig. Codex CLI, Cursor IDE und Pi laufen mit Einschränkungen: bei Codex CLI ist die Schreibgrenze eine Vereinbarung statt ein Mechanismus, Cursor IDE prüft im Nachhinein, Pi ist über eine Brücke angebunden. Im Installations-Abschnitt steht der Weg für jedes davon.

Was ist der Unterschied zu Claude Code allein?

Vier Dinge: der Lese-Schritt vor jeder Änderung, ein Plan, dem du zustimmst, eine kurze Dateiliste pro Schritt, und eine automatische Prüfung dazwischen. Ohne die fängt das Werkzeug beim ersten Satz zu tippen an.

Schickt es Daten irgendwohin?

Kein Konto und kein Server. Alles läuft auf deinem Rechner. Nutzungsdaten werden nur geschickt, wenn du das einschaltest. Ab Werk ist das aus. Diese Website lädt nichts von einer fremden Domain.

Läuft es unter Windows?

Es läuft nativ unter Windows, aber Windows ist von den automatischen Testläufen nicht abgedeckt. macOS und Linux schon, also sind das die beiden Wege, die bei jeder Änderung geprüft werden.

Was kostet es?

Nichts. Es ist kostenlos und Open Source unter der MIT-Lizenz. Was dein Code-Werkzeug kostet, zahlst du weiterhin; daran ändert sich nichts.

Kann es mein Projekt kaputt machen?

Zerstörerische Shell-Befehle blockt eine Policy-Datei, keine höfliche Anweisung. Es überschreibt nie die bisherige Änderungsgeschichte deines Projekts. Es speichert die Änderungen am Ende einer Session fest, nachdem die Prüfungen gelaufen sind, und sagt dir, was es gespeichert hat.

Wer pflegt das?

Eine Person, Bernhard Götzendorfer. Fragen und Fehlermeldungen auf GitHub beantwortet er selbst. Du kriegst es so, wie es ist. Er pflegt es, so gut es sich ausgeht, sagt aber keine Antwortzeit zu.

09 / Grenzen

Was das ist, und was nicht

  • Unabhängig und von der Community gepflegt. Nicht verbunden mit Anthropic, OpenAI oder Cursor und von keiner dieser Firmen unterstützt.
  • Ausgeliefert wie es ist, ohne zugesicherte Reaktionszeiten, Pflege nach bestem Bemühen.
  • Lokal per Default. Kein Konto, kein Server. Nutzungsdaten werden nur geschickt, wenn du das einschaltest. Ab Werk ist das aus.
  • macOS und Linux sind voll unterstützt und von der CI abgedeckt. Windows läuft nativ, ist aber nicht CI-abgedeckt.
  • Eine Rangliste gibt es noch nicht, und auch keine Gesamtnote. Wo eine Zahl fehlt, steht das dort, statt zu raten. Eine Rangliste auf einer Messmethode, die noch nicht ehrlich ist, wäre schlechter als keine.
  • Die Durchsetzung auf Hook-Ebene ist nicht auf jeder Umgebung gleich. Die Liste unten ist der aktuelle Stand, keine Roadmap. Die Prüfungen sind überall identisch.
