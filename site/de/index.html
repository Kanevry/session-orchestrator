Fünf Schritte.
Du tippst drei Befehle.

Eine Aufgabe von Anfang bis Ende: „Füge dem Dashboard einen CSV-Export hinzu.“ Die Aufgabe ist ein Beispiel; die Befehle und die Schritte sind echt.

Einmal pro Repository, vor der ersten Session Tippe /bootstrap. Es richtet dein Repository ein; mit --fast --no-interview ohne Rückfragen. Danach brauchst du pro Aufgabe nur noch die drei Befehle unten. Auf Codex wählst du jeden Befehl als Skill: $session-orchestrator:bootstrap, $session-orchestrator:session, $session-orchestrator:go, $session-orchestrator:close.

  1. Du tippst/session feature add a CSV export

    Es liest deinen Code, offene Issues, die letzten Commits und die letzte Session und schlägt dann einen Plan vor. Noch hat sich nichts geändert.

  2. Du tippst/go

    Korrigiere den Plan, indem du in den Chat schreibst, oder sag Ja, indem du /go tippst. Jeder Agent bekommt seine eigene Dateiliste, und Überschneidungen werden vor dem Start abgelehnt.

  3. Du tustnichts. Schau zu oder mach etwas anderes.

    Die Agents arbeiten in Runden: nebeneinander auf Claude Code und Codex, nacheinander auf Cursor und Pi.

  4. Du tustnichts.

    Nach jeder Runde laufen deine Tests und der Typecheck. Ein fehlgeschlagener Test wird zur Korrekturaufgabe für die nächste Runde, so wird der Fehler in der Runde gefunden, die ihn gemacht hat.

  5. Du tippst/close

    Es macht die volle Prüfung, vergleicht das Ergebnis mit dem Plan, committet die Arbeit und macht aus Offenem Issues. Die nächste /session beginnt hier.

Nichts geht verloren.

Ein Absturz, ein zugeklappter Laptop oder ein langes Wochenende kosten dich nicht die Arbeit. STATE.md hält jede fertige Runde fest, also bietet die nächste /session an, dort fortzusetzen. Was /close nicht fertigstellen konnte, wartet als Issue auf GitLab oder GitHub.

Wie alles zusammenpasst

Dein Tool schreibt den Code.
Dieses Plugin hält die Arbeit in Ordnung.

Es ist keine weitere KI. Es gibt dem Coding-Tool, das du schon nutzt, eine feste Arbeitsweise, und alles, was es aufbewahrt, ist reiner Text in deinem Repository.

  • In deinem Repository: reiner Text, den du lesen und löschen kannst. STATE.md für die laufende Session, Regeln unter .claude/rules/.
  • Auf GitLab oder GitHub: ein Issue für jede offene Sache, damit nichts vergessen wird.
  • Sonst nirgends: kein eigenes Konto und kein eigener Server. Standardmäßig spricht das Plugin außer mit deinem Coding-Tool und deinem Git-Host nur mit npm, um nach Updates zu fragen, und das kannst du abschalten. Funktionen, die du selbst einschaltest, etwa Nutzungsdaten oder entfernte Rechner, bauen eigene Verbindungen auf. Optionale Nutzungsdaten bleiben aus, bis du zustimmst.

Es lernt, mit deinem Ja

Derselbe Fehler soll nicht
jede Woche wiederkommen.

Jede Session hinterlässt eine kurze Aufzeichnung. /evolve schaut über diese Aufzeichnungen und schlägt eine Lehre vor. Du entscheidest. Nur eine Lehre, die du behältst, kann zur Regel werden.

  1. 1Eine Session hinterlässt eine Aufzeichnung

    Eine Zeile pro Session: ihr Typ, ihre Runden und Agents, was fertig wurde und was weitergetragen wurde.

    .orchestrator/metrics/sessions.jsonl

  2. 2/evolve schlägt eine Lehre vor

    Sie zeigt die Belege, einen Konfidenzwert und die Dateien, um die es in der Lehre geht. Die echte Lehre unten betrifft die eigenen Werkzeuge dieses Projekts. In deinem Repository geht es um deinen Code, zum Beispiel um eine Prüfung, die deine Agents immer wieder auslassen.

    { "type": "convention",
  "evidence": "Session … three reviews against …",
  "file_paths": ["skills/_shared/fleet-protocol.md",
                 "skills/wave-executor/SKILL.md"],
  "expires_at": "2027-01-12T00:10:00.000Z" }

  3. 3Du entscheidest

    Behalten, korrigieren oder verwerfen. Ohne dich wird nichts zur Regel.

    BehaltenKorrigierenVerwerfen

  4. 4/reconcile schreibt eine Regel

    Eine kleine Regeldatei, die ihre Quelle, ihre Konfidenz und ein Ablaufdatum nennt.

    auto-generated: true
paths:
  - "skills/_shared/**"
  - "skills/wave-executor/**"
learning-key: convention/owner-inbox-…
confidence: 0.8
expires-at: 2027-01-12

  5. 5Die nächste Session nutzt sie

    Agents bekommen die Regel nur, wenn sie an passenden Dateien arbeiten. Nach dem Ablaufdatum entfernt Housekeeping sie, sobald du zustimmst.

Die Beispiele in Schritt 2 und 4 sind echte Dateien aus diesem Repository, gekürzt.

Was, wann?

/plan retro
nach einer abgeschlossenen Phase: was gut lief, was sich ändern soll
/evolve
wenn sich in deinen Sessions ein Muster wiederholt
/reconcile
wenn eine behaltene Lehre zur wirksamen Regel werden soll
/eval
um zu bewerten, wie eine Session gelaufen ist, aus ihren eigenen Aufzeichnungen
/session housekeeping
um die ganze Pflege in einem Durchgang zu erledigen

Was es nicht tut: Es trainiert kein Modell, und es ändert sich nicht ohne deine Zustimmung. Gemessene Tests, die zwei Versionen eines Skills vergleichen, sind geplant, nicht ausgeliefert.

Wähle deinen Installationsweg. Du brauchst Node.js 24 oder neuer und ein Git-Repository. Das Plugin ist kostenlos; die Kosten deines Coding-Tools bleiben davon unabhängig.

Nur wenn ein Befehl fehlschlägt: Node-Abhängigkeiten einmal prüfen

Aktuelles Claude Code installiert die Node-Abhängigkeiten mit dem Plugin. Zum einmaligen Prüfen, oder falls das bei dir nicht passiert ist, den Befehl unten in einer Shell ausführen: er startet npm install nur, wenn die Abhängigkeiten fehlen. Danach Claude Code neu starten, falls er installiert hat.

claude plugin list --json

Suche den aktivierten Eintrag session-orchestrator@kanevry. Ersetze den Platzhalter unten durch dessen installPath. Fehlt der Eintrag oder ist er deaktiviert, kläre das zuerst über /plugin. Bei mehreren Treffern die aktive Installation prüfen.

cd "/absolute/installPath/from/the/list" && { [ -d node_modules/js-yaml ] && echo "dependencies present, nothing to do" || npm install; }

node scripts/codex-install.mjs

Braucht Codex CLI ab 0.144.4. Die Konfiguration steht in AGENTS.md. Öffne nach der Installation eine neue Aufgabe und prüfe die Plugin-Hooks über /hooks.

Wähle die Session-Orchestrator-Skills: $session-orchestrator:bootstrap, danach $session-orchestrator:session feature, $session-orchestrator:go und $session-orchestrator:close. Siehe die Anleitung zur ersten Session (Englisch).

Auf Codex blockieren die Bash-Guards, die Schreibgrenze nicht. Der Guard für zerstörerische Befehle und die übrigen Bash-Guards laufen als Hooks, und Codex hält sich an ihre Ablehnung. Die Schreibgrenze bleibt eine Anweisung, weil Codex Dateien über apply_patch ändert und der Scope-Guard das nicht liest. Die Workflows und Qualitätsprüfungen laufen weiterhin.

Häufige Fragen

Fragen, die Leute stellen

Ist das selbst ein Werkzeug, das Code schreibt?

Nein. Es ergänzt einen Ablauf zum Planen, Arbeiten und Prüfen der Ergebnisse. Den Code schreibt dein Code-Werkzeug. Welche Grenzen technisch durchgesetzt werden, hängt vom Werkzeug und der Konfiguration der Guards ab.

Mit welchen Werkzeugen läuft es?

Claude Code führt die Guard-Hooks direkt aus. Cursor und Pi nutzen Brücken mit dokumentierten Grenzen. Codex CLI bietet auswählbare Workflow-Skills und führt den Guard für zerstörerische Befehle als Bash-Hook aus, der blockiert; die Regeln für Schreibbereiche sind dort nur Anweisungen, weil Codex Dateien über apply_patch ändert und der Scope-Guard das nicht liest. Parallele Agenten gibt es auf Claude Code und Codex; Cursor und Pi arbeiten Aufgaben nacheinander ab.

Was ist der Unterschied zu Claude Code allein?

Es ergänzt einen wiederholbaren Ablauf: Projekt lesen, Umfang abstimmen, die Arbeit in Schritte mit festgelegten Dateien teilen und die Ergebnisse dazwischen prüfen. Der Session-Eintrag hält Fortschritt und offene Arbeit für die nächste Session fest.

Schickt es Daten irgendwohin?

Das Plugin läuft lokal ohne eigenes Konto. Optionale Nutzungsstatistik ist bis zu deiner Zustimmung ausgeschaltet. Beim Session-Start fragt es standardmäßig die npm-Registry nach Updates ab. Erfolgreiche Ergebnisse werden pro Repository 24 Stunden zwischengespeichert; schlägt die Anfrage oder das Speichern fehl, kann die nächste Session erneut anfragen. SO_DISABLE_UPDATE_CHECK=1 oder DO_NOT_TRACK=1 schaltet die Prüfung aus. Dein Code-Werkzeug und eingerichtete Dienste nutzen weiterhin ihre eigenen Netzwerkverbindungen. Diese Website nutzt cookiefreie Vercel Web Analytics, beschrieben in der Datenschutzerklärung.

Läuft es unter Windows?

macOS und Linux werden in der CI geprüft. Native Windows-Nutzung ist nicht getestet. Der Node-Kern nutzt portable Pfade, aber die Shell-Hooks und der optionale MCP-Server brauchen WSL oder Git Bash. Windows-Unterstützung erfolgt nach bestem Bemühen.

Was kostet es?

Für das Plugin nichts. Es ist kostenlos und Open Source unter der MIT-Lizenz. Dein Code-Werkzeug zahlst du weiterhin, und eine Session mit mehreren Agents und Runden verbraucht mehr von seinem Kontingent oder seinen Tokens als ein einzelner Chat.

Kann es mein Projekt kaputt machen?

Fehler sind weiterhin möglich. Auf Claude Code und Codex wendet ein aktiver Hook für zerstörerische Befehle 13 blockierende und 4 warnende Regeln an. Cursor und Pi nutzen Brücken mit dokumentierten Grenzen. Codex setzt den Guard für Schreibbereiche nicht technisch durch. Bei unterstützten Änderungen mit aktivem Scope-Hook blockiert strict Verstöße, warn meldet sie und off deaktiviert die Prüfung. Prüfe Änderungen und halte Sicherungen vor; die Prüfungen garantieren keinen korrekten Code.
