Plan / Go / Close

Eine Session.
Ein nachvollziehbarer Ablauf.

Ein gemeinsamer Plan, klar verteilte Aufgaben und ein Abschluss, an den du beim nächsten Mal anknüpfen kannst.

Beispielsession

„Füge dem Dashboard einen CSV-Export hinzu.“

Illustrativer Ablauf, kein Live-Bericht
  1. 01

    Plan

    Erst verstehen, dann aufteilen.

    Code, offene Issues und bestehende Tests prüfen. Das Ziel eingrenzen, bevor jemand Dateien ändert.

    Export-Code lesenDatenzugriff prüfenTests sichten

    Zusammenführen: Ein gemeinsamer Plan für Export-Button, CSV-Format und Download. Die Schreibbereiche werden vorab zugeordnet.

  2. 02

    Go

    Unabhängig arbeiten. Gemeinsam prüfen.

    Oberfläche

    Button und leeren Zustand umsetzen.

    Daten

    CSV-Ausgabe und Sonderzeichen behandeln.

    Prüfen: Änderungen zusammenführen. Download, Format und Fehlerfälle testen. Befunde korrigieren, dann erneut prüfen.

    Claude Code und Codex können unabhängige Aufgaben parallel ausführen. Cursor und Pi arbeiten sie nacheinander ab.

  3. 03

    Close

    Festhalten, was erledigt ist. Und was offen bleibt.

    Erledigt CSV-Export umgesetzt und die vereinbarten Fälle geprüft.

    Noch offen Frei wählbare Spalten als Folgeaufgabe festhalten.

    Änderungen, Prüfnachweise und nächste Schritte bleiben für die nächste Session nachvollziehbar.

Die Aufgabe bestimmt den Umfang.

Housekeeping kann mit einer Welle auskommen. Deep nutzt fünf, das Ultradeep-Profil sieben. Die Wellen strukturieren die Arbeit; sie sind kein Grund, aus jeder kleinen Änderung ein großes Projekt zu machen.

Installation

Dein Tool.
Deine nächste Session.

Wähle deinen Installationsweg. Du brauchst Node.js 24 oder neuer und ein Git-Repository. Das Plugin ist kostenlos; die Kosten deines Coding-Tools bleiben davon unabhängig.

Claude CodePlugin-Marketplace

/plugin marketplace add Kanevry/session-orchestrator

/plugin install session-orchestrator@kanevry

Danach einmal npm install im Plugin-Cache laufen lassen und Claude Code neu starten.

claude plugin list --json

Suche den aktivierten Eintrag session-orchestrator@kanevry. Ersetze den Platzhalter unten durch dessen installPath. Fehlt der Eintrag oder ist er deaktiviert, kläre das zuerst über /plugin. Bei mehreren Treffern die aktive Installation prüfen.

cd "/absolute/installPath/from/the/list" && npm install

Codex CLIKlonen und Installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/codex-install.mjs

Braucht Codex CLI ab 0.144.4. Die Konfiguration steht in AGENTS.md. Öffne nach der Installation eine neue Aufgabe und prüfe die Plugin-Hooks über /hooks.

Wähle die Session-Orchestrator-Skills: $session-orchestrator:bootstrap, danach $session-orchestrator:session feature, $session-orchestrator:go und $session-orchestrator:close. Siehe den Guide zur ersten Session (EN).

Beide Guards sind auf Codex nur Anweisungen. Das Plugin setzt weder die Regeln für zerstörerische Befehle noch die Schreibgrenze technisch durch. Die Workflows und Qualitätsprüfungen laufen weiterhin.

Cursor IDEKlonen und Installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/cursor-install.mjs /absolute/path/to/your/project

Zielprojekt. Gib den Projektpfad ausdrücklich an. Ohne Pfad verwendet der Installer das aktuelle Verzeichnis.

PiPaketmanager

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

pi install npm:session-orchestrator

Dieser Weg installiert seine Abhängigkeiten selbst; die anderen drei brauchen einmal npm install.

Noch nicht eingerichtet? Der Guide führt dich durch Installation und Bootstrap.

Unterstützte Tools und Grenzen
  • Unabhängig und von der Community gepflegt. Nicht verbunden mit Anthropic, OpenAI oder Cursor und von keiner dieser Firmen unterstützt.
  • Ausgeliefert wie es ist, ohne zugesicherte Reaktionszeiten, Pflege nach bestem Bemühen.
  • Lokal per Default, ohne eigenes Konto. Optionale Nutzungsstatistik ist ausgeschaltet; die npm-Update-Abfrage lässt sich separat deaktivieren.
  • macOS und Linux werden in der CI geprüft. Native Windows-Nutzung ist ungetestet; Shell-Hooks und der optionale MCP-Server brauchen WSL oder Git Bash.
  • Eine Rangliste gibt es noch nicht, und auch keine Gesamtnote. Wo eine Zahl fehlt, steht das dort, statt zu raten. Eine Rangliste auf einer Messmethode, die noch nicht ehrlich ist, wäre schlechter als keine.
  • Die Durchsetzung auf Hook-Ebene ist nicht auf jeder Umgebung gleich. Die Liste unten ist der aktuelle Stand, keine Roadmap. Die konfigurierten Qualitätsprüfungen laufen auf allen vier Werkzeugen.

Häufige Fragen

Fragen, die Leute stellen

Ist das selbst ein Werkzeug, das Code schreibt?

Nein. Es ergänzt einen Ablauf zum Planen, Arbeiten und Prüfen der Ergebnisse. Den Code schreibt dein Code-Werkzeug. Welche Grenzen technisch durchgesetzt werden, hängt vom Werkzeug und der Konfiguration der Guards ab.

Mit welchen Werkzeugen läuft es?

Claude Code führt die Guard-Hooks direkt aus. Cursor und Pi nutzen Brücken mit dokumentierten Grenzen. Codex CLI bietet auswählbare Workflow-Skills, behandelt die Regeln für zerstörerische Befehle und Schreibbereiche aber nur als Anweisungen; das Plugin setzt beide Guards dort nicht technisch durch. Parallele Agenten gibt es auf Claude Code und Codex; Cursor und Pi arbeiten Aufgaben nacheinander ab.

Was ist der Unterschied zu Claude Code allein?

Es ergänzt einen wiederholbaren Ablauf: Projekt lesen, Umfang abstimmen, die Arbeit in Schritte mit festgelegten Dateien teilen und die Ergebnisse dazwischen prüfen. Der Session-Eintrag hält Fortschritt und offene Arbeit für die nächste Session fest.

Schickt es Daten irgendwohin?

Das Plugin läuft lokal ohne eigenes Konto. Optionale Nutzungsstatistik ist bis zu deiner Zustimmung ausgeschaltet. Beim Session-Start fragt es standardmäßig die npm-Registry nach Updates ab. Erfolgreiche Ergebnisse werden pro Repository 24 Stunden zwischengespeichert; schlägt die Anfrage oder das Speichern fehl, kann die nächste Session erneut anfragen. SO_DISABLE_UPDATE_CHECK=1 oder DO_NOT_TRACK=1 schaltet die Prüfung aus. Dein Code-Werkzeug und eingerichtete Dienste nutzen weiterhin ihre eigenen Netzwerkverbindungen. Diese Website nutzt cookiefreie Vercel Web Analytics, beschrieben in der Datenschutzerklärung.

Läuft es unter Windows?

macOS und Linux werden in der CI geprüft. Native Windows-Nutzung ist nicht getestet. Der Node-Kern nutzt portable Pfade, aber die Shell-Hooks und der optionale MCP-Server brauchen WSL oder Git Bash. Windows-Unterstützung erfolgt nach bestem Bemühen.

Was kostet es?

Nichts. Es ist kostenlos und Open Source unter der MIT-Lizenz. Was dein Code-Werkzeug kostet, zahlst du weiterhin; daran ändert sich nichts.

Kann es mein Projekt kaputt machen?

Fehler sind weiterhin möglich. Auf Claude Code wendet ein aktiver Hook für zerstörerische Befehle 10 blockierende und 4 warnende Regeln an. Cursor und Pi nutzen Brücken mit dokumentierten Grenzen. Codex setzt weder diesen Guard noch den Guard für Schreibbereiche technisch durch. Bei unterstützten Änderungen mit aktivem Scope-Hook blockiert strict Verstöße, warn meldet sie und off deaktiviert die Prüfung. Prüfe Änderungen und halte Sicherungen vor; die Prüfungen garantieren keinen korrekten Code.
