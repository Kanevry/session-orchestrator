Claude Code

Everything works here: agents run in parallel, and the guards block.

  1. You need Terminal

    Node.js 24 or later (check with node --version), a Git repository and Claude Code.

  2. Install Chat in your coding tool

    /plugin marketplace add Kanevry/session-orchestrator

    /plugin install session-orchestrator@kanevry

    Current Claude Code installs the Node dependencies itself. Only if a command fails, use the dependency check.

  3. Set up once Chat in your coding tool

    /bootstrap --fast --no-interview

    No questions, sensible defaults. If you want to choose the settings yourself, run /bootstrap and answer the interview.

  4. Your first session Chat in your coding tool

    /session feature add a CSV export

    Then /go, then /close.

    What the three commands do
    /sessionreads your repository and proposes what to work on; nothing changes until you agree
    /godoes the agreed work in rounds (waves) and checks each round with your tests
    /closeruns the full check, commits, and writes down what is left as issues

  5. What success looks like

    You see a short report and a proposed plan. Nothing in your code has changed yet. You answer with /go or correct the plan.

    After /close you see what was done, what was checked and which issues were opened for the rest.

Last documented install run: 2026-10-26, plugin 5.13.0, Claude Code 2.1.310 on macOS, from the curated GitHub snapshot in an empty profile. marketplace add and install exit 0, all runtime dependencies present, SessionStart hook exit 0. A session with model calls was not part of the run, because the empty profile had no login.

Codex CLI

Everything works here, with one difference: the file list is an instruction. Codex edits files through apply_patch, which the file-scope guard does not read. The guard for dangerous commands blocks.

  1. You need Terminal

    Node.js 24 or later, a Git repository and Codex CLI 0.144.4 or later.

  2. Install Terminal

    git clone https://github.com/Kanevry/session-orchestrator.git

    cd session-orchestrator && npm install

    node scripts/codex-install.mjs

    Then start a fresh Codex task and review the plugin hooks once with /hooks.

  3. Set up once Chat in your coding tool

    $session-orchestrator:bootstrap

  4. Your first session Chat in your coding tool

    $session-orchestrator:session feature add a CSV export

    Then $session-orchestrator:go, then $session-orchestrator:close. These are skill picks in the Codex chat. Plain /go and /close do not work in Codex.

  5. What success looks like

    You see a short report and a proposed plan. Nothing in your code has changed yet. You answer with $session-orchestrator:go or correct the plan.

    After $session-orchestrator:close you see what was done, what was checked and which issues were opened for the rest.

Last documented install run: 2026-10-26, plugin 5.13.0, Codex CLI 0.160.1 on macOS, from the curated GitHub snapshot in an empty profile. The short marketplace form and the clone installer above both exit 0, the plugin is installed and enabled. A session with model calls was not part of the run, because the empty profile had no login.

Cursor IDE

The same workflow, but agents run one after another. The guards run through a bridge.

  1. You need Terminal

    Node.js 24 or later, a Git repository and Cursor IDE.

  2. Install Terminal

    git clone https://github.com/Kanevry/session-orchestrator.git

    cd session-orchestrator && npm install

    node scripts/cursor-install.mjs /absolute/path/to/your/project

    Give the absolute path of your project. Without it, the installer uses the current directory.

  3. Set up once Chat in your coding tool

  4. Your first session Chat in your coding tool

    /session feature add a CSV export

    Then /go, then /close.

  5. What success looks like

Before you start: requirements and the instruction file

macOS and Linux are covered by CI. Native Windows is untested; the shell hooks and the optional MCP server need WSL or Git Bash. Some optional workflows (the plugin validator, some wave-scope snippets, the MCP server) also need jq.

Your settings live in the project’s instruction file: CLAUDE.md on Claude Code and Cursor, AGENTS.md on Codex CLI and Pi. The contents are the same.

Each tool keeps its own session notes (STATE.md in .claude/, .codex/, .cursor/ or .pi/). Session records and lessons in .orchestrator/metrics/ are shared, and so are the issues. Switching tools keeps your history.

Configuration: the Session Config

Bootstrap writes this block for you. These seven fields are the minimum:

## Session Config

test-command: npm test
typecheck-command: npm run typecheck
lint-command: npm run lint
agents-per-wave: 6
waves: 5
persistence: true
enforcement: warn

The heading must read ## Session Config exactly. Pasting the block alone does not finish setup: bootstrap also writes .orchestrator/bootstrap.lock, so run bootstrap once.

enforcement takes strict (edits outside the file list are blocked), warn (they are reported) or off. Every key: configuration reference.

What the guards block, and where they stop

The guard for dangerous commands follows .orchestrator/policy/blocked-commands.json: 14 blocking and 4 warning rules. It blocks hard resets, discarding checkouts, forced cleaning, destructive removal, force-push, SQL DROP TABLE and deleting the session records. It warns on soft resets, stash and git push --force-with-lease.

Guard behaviour per coding tool
ToolDangerous commandsEdits outside the file list
Claude Codeblocked by a hookblocked in strict
Codex CLIblocked by a hook (Codex honours the deny)an instruction only
Cursor IDEthrough a bridgeblocked in strict
Pithrough a bridgeblocked in strict

A file list is not filesystem isolation. Several sessions can share one working copy, which is why a stash or a reset is guarded: it can take a neighbour’s work.

What to do when a command is blocked

Read the reason in the message first. Most blocks protect work you did not create.

If you really mean it, set allow-destructive-ops: true in the Session Config for that maintenance and remove it afterwards. Left in place, it turns the guard off for every later session.

If a legitimate edit is blocked by the file list, check the plan and the other agents’ files before you add the path. enforcement: off turns off the file-list check only, not the guard for dangerous commands.

When something goes wrong

A command fails right after installing on Claude Code. Check the dependencies once. In a terminal, run claude plugin list --json, take the installPath of the enabled session-orchestrator@kanevry entry, then:

cd "/absolute/installPath/from/the/list" && { [ -d node_modules/js-yaml ] && echo "dependencies present" || npm install; }

If it installed anything, restart Claude Code.

Hooks cannot find Node. Hooks run in your coding tool’s environment, not your login shell. Set SO_NODE_BIN to the absolute path of your Node binary, or start the tool from a shell where node works.

Cursor files landed in the wrong project. Rerun the installer with the absolute project path.

The summary does not match what you saw. Compare it with the latest session record:

tail -1 .orchestrator/metrics/sessions.jsonl | jq '{session_id, total_waves, total_agents, total_files_changed}'

Look closer at total_agents: 0 after agents plainly worked, undefined anywhere, or -abandoned- in the id after a clean /close. Then check what actually changed on disk before you build on it. Still stuck: open an issue.
