Try a checked coding session in one afternoon.

Session Orchestrator is an open-source tool for software teams using AI coding agents. Agree on a plan, check the work with your project’s own commands, and leave a written handover.

EUR 0. The tool is MIT-licensed. Session Orchestrator runs locally in your Git repository without a Session Orchestrator account or server. The coding agent supplies the model. Its provider may charge separately.

By default, the plugin checks the npm registry for updates. Its security check fetches the Node.js release index and the CISA KEV feed. It filters out private packages before sending package names and versions from your lockfile to OSV. For GitHub remotes, it also uses gh to check for private vulnerability reports. Set SO_DISABLE_UPDATE_CHECK=1 to turn off the update check and SO_SECURITY_PULSE_REFRESH=off to turn off the security check. Either DO_NOT_TRACK=1 or CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 turns off both. Telemetry is off unless you opt in. See network connections in the guide.

From installation to handover

An EDIH adviser and a developer can try this together. Bring Node.js 24 or later, a Git repository with working checks, and a small change the team can review that afternoon.

  1. Install Session Orchestrator inside Claude Code with /plugin marketplace add Kanevry/session-orchestrator and then /plugin install session-orchestrator@kanevry. For Codex CLI, Cursor or Pi, follow the installation guide for your coding agent.
  2. Open the project in the coding agent and run /bootstrap to set up Session Config. Set test-command, typecheck-command and lint-command to the project’s own commands. In an npm project these might be npm test, npm run typecheck and npm run lint.
  3. Start with /session feature and review and agree on the plan. Run /go for the first round and review the check results. Run /close and read the handover together. The user guide explains how to invoke the workflow in each coding agent.

Pi and model hosting

On Pi, tasks run sequentially and hook context intended for the model is unavailable. Live Pi compatibility has not yet been verified in a recorded run. Two end-to-end recordings are planned, one with a European model provider and one with a model on hardware operated by the project. Each setup counts as verified once a recorded run meets the published criteria.
