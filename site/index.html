How it works

Five steps.
You type three commands.

One task from start to finish: “Add a CSV export to the dashboard.” The task is an example; the commands and the steps are the real ones.

Once per repository, before the first session Type /bootstrap. It sets up your repository; add --fast --no-interview to skip its questions. After that, each task needs only the three commands below. On Codex you pick every command as a skill: $session-orchestrator:bootstrap, $session-orchestrator:session, $session-orchestrator:go, $session-orchestrator:close.

  1. You type/session feature add a CSV export

    It reads your code, open issues, recent commits and the last session, then proposes a plan. Nothing has changed yet.

  2. You type/go

    Correct the plan by writing in the chat, or say yes by typing /go. Every agent gets its own list of files, and overlaps are rejected before work starts.

  3. You donothing. Watch, or do something else.

    The agents work in rounds: side by side on Claude Code and Codex, one after another on Cursor and Pi.

  4. You donothing.

    After each round your tests and typecheck run. A failing test becomes a fix task for the next round, so the error is caught in the round that made it.

  5. You type/close

    It runs the full check, compares the result with the plan, commits the work and turns what is left into issues. The next /session starts here.

Nothing gets lost.

A crash, a closed laptop or a long weekend does not cost you the work. STATE.md records every finished round, so the next /session offers to resume. What /close could not finish is waiting as an issue on GitLab or GitHub.

How it fits together

Your tool writes the code.
This plugin keeps the work in order.

It is not another AI. It adds a fixed way of working to the coding tool you already use, and everything it keeps is plain text in your repository.

  • In your repository: plain text you can read and delete. STATE.md for the running session, rules under .claude/rules/.
  • On GitLab or GitHub: one issue for each thing that is left, so it cannot be forgotten.
  • Nowhere else: no account and no server of its own. By default, besides your coding tool and your Git host, the plugin only asks npm for updates, and you can switch that off. Features you turn on yourself, such as usage data or remote hosts, make their own connections. Optional usage data stays off until you agree.

It learns, with your yes

The same mistake should not
come back every week.

Each session leaves a short record. /evolve looks across those records and suggests a lesson. You decide. Only a lesson you keep can become a rule.

  1. 1A session leaves a record

    One line per session: its type, its rounds and agents, what was finished and what was carried over.

    .orchestrator/metrics/sessions.jsonl

  2. 2/evolve suggests a lesson

    It shows the evidence, a confidence score and the files the lesson is about. The real lesson below is about this project’s own tools. In your repository a lesson is about your code, for example a check your agents keep skipping.

    { "type": "convention",
  "evidence": "Session … three reviews against …",
  "file_paths": ["skills/_shared/fleet-protocol.md",
                 "skills/wave-executor/SKILL.md"],
  "expires_at": "2027-01-12T00:10:00.000Z" }

  3. 3You decide

    Keep it, correct it or reject it. Nothing becomes a rule without you.

    KeepCorrectReject

  4. 4/reconcile writes a rule

    A small rule file that names its source, its confidence and an expiry date.

    auto-generated: true
paths:
  - "skills/_shared/**"
  - "skills/wave-executor/**"
learning-key: convention/owner-inbox-…
confidence: 0.8
expires-at: 2027-01-12

  5. 5The next session uses it

    Agents get the rule only when they work on matching files. After its expiry date, housekeeping removes it once you confirm.

The examples in steps 2 and 4 are real files from this repository, shortened.

Which one, when?

/plan retro
after a finished phase: what worked, what to change
/evolve
when your sessions repeat a pattern
/reconcile
when a lesson you kept should become a working rule
/eval
to score how a session ran, from its own records
/session housekeeping
to do all the upkeep in one go

What it does not do: it does not train a model, and it does not change itself without your approval. Measured tests that compare two versions of a skill are planned, not shipped.

My recommendation

Want every guard to block, and the lead Inbox? Use Claude Code. Prefer Codex? You get the same commands as skills, agents side by side and the command guard. It started with
a Notion page.

I kept 20–30 prompts there for different projects. Before each session I would find the right row, copy it, and explain how I wanted to work all over again.

That routine gradually became Plan, Go, Close. I now use it on my Mac M4 and the M5 at the office. Session Orchestrator is the tool that grew out of it.

Install

Your tool.
Your next session.

Choose your installation path. You need Node.js 24 or later and a Git repository. The plugin is free; your coding tool has its own costs.

Claude Codeplugin marketplace

/plugin marketplace add Kanevry/session-orchestrator

/plugin install session-orchestrator@kanevry

Only if a command fails: check the Node dependencies once

Current Claude Code installs the Node dependencies with the plugin. To check once, or if yours did not, run the command below in a shell: it runs npm install only when the dependencies are missing. Restart Claude Code if it did.

claude plugin list --json

Find the enabled session-orchestrator@kanevry entry. Replace the placeholder below with its installPath. If the entry is missing or disabled, resolve that through /plugin first. If several entries match, check the active installation instead of guessing.

cd "/absolute/installPath/from/the/list" && { [ -d node_modules/js-yaml ] && echo "dependencies present, nothing to do" || npm install; }

Codex CLIclone and installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/codex-install.mjs

Requires Codex CLI 0.144.4 or later. Config goes in AGENTS.md. After installation, open a fresh task and review the plugin hooks through /hooks.

Select the Session Orchestrator skills: $session-orchestrator:bootstrap, then $session-orchestrator:session feature, $session-orchestrator:go, and $session-orchestrator:close. See the first-session guide.

On Codex the Bash guards block; the file-scope guard does not. The destructive-command guard and the other Bash guards run as hooks, and Codex honours their deny. The file-scope guard stays an instruction, because Codex edits files through apply_patch, which the scope guard does not read. The workflows and quality checks still run.

Cursor IDEclone and installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/cursor-install.mjs /absolute/path/to/your/project

Target project. Pass the target project explicitly. Without a path, the installer uses the current directory.

Pipackage manager

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

pi install npm:session-orchestrator

This path installs its own dependencies; the Codex CLI and Cursor clones need npm install once.

Supported tools and limitations
  • Independent and community-maintained. Not affiliated with or endorsed by Anthropic, OpenAI, or Cursor.
  • Shipped as-is, with no service level agreement and best-effort maintenance.
  • Local by default, without its own account. Optional telemetry is off; the npm update check can be disabled separately.

A few practical questions

Questions people ask

Setup steps for each tool are in the guide.

Is this itself an AI that writes code?

No. It adds a workflow for planning, working and checking results. Your coding tool writes the code. Technical enforcement depends on the tool and guard configuration.

Which tools does it work with?

Claude Code runs the guard hooks directly. Cursor and Pi use bridges with documented limits. Codex CLI offers selectable workflow skills and runs the destructive-command guard as a Bash hook that blocks; its file-scope rules are instructions only, because Codex edits files through apply_patch, which the scope guard does not read. Parallel agents are available on Claude Code and Codex; Cursor and Pi run tasks sequentially.

Can a team use it?

Yes. Each person installs the plugin in their own coding tool. The Session Config in CLAUDE.md and the session records under .orchestrator/ live in the repository and are committed, so the next person's session reads what the last one left. Commits land on the branch you are on; /close pushes that branch. It creates a new branch only when you accept a worktree offer or run /autopilot.

What happens to my existing CLAUDE.md?

/bootstrap never overwrites it. It only adds the sections it needs (## Session Config, ## Dispatcher Autonomy and a short rules section) when they are missing.

Does it work with Jira or Linear?

No. Issues are read and written on GitHub or GitLab only.

What is different from just using Claude Code?

It adds a repeatable session workflow: read the project, agree the scope, divide the work into steps with declared files, and check the results between steps. The session record carries progress and unfinished work into the next session.

Does it send data anywhere?

The plugin runs locally without its own account. Optional usage telemetry is off until you consent. By default, session-start checks the npm registry for updates. Successful results are cached for 24 hours per repository; a failed request or cache write may cause another request at the next session. SO_DISABLE_UPDATE_CHECK=1 or DO_NOT_TRACK=1 disables the check. Your coding tool and configured services still use their own network connections. This website uses cookieless Vercel Web Analytics, described in its privacy policy.

Does it work on Windows?

macOS and Linux are covered by CI. Native Windows use has not been tested. The Node core uses portable paths, but the shell-based hooks and optional MCP server need WSL or Git Bash. Treat Windows support as best-effort.

What does it cost?

Nothing for the plugin. It is free and open source under the MIT licence. You still pay for your coding tool, and a session with several agents and rounds uses more of its quota or tokens than a single chat.

Can it break my project?

It can still make mistakes. On Claude Code and Codex, an active destructive-command hook applies 14 blocking rules and 4 warning rules. Cursor and Pi use bridges with documented limits. Codex does not enforce the file-scope guard. For supported edits with an active scope hook, strict blocks violations, warn reports them, and off disables the check. Review changes and keep backups; the checks do not guarantee correct code.

Who maintains it?

Me, Bernhard Götzendorfer. I answer questions on GitHub myself. It is shipped as-is, with best-effort maintenance and no service level agreement.
