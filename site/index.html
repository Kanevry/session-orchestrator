01 / What it is

It reads first, asks, then works in checked steps.

Session Orchestrator is a free extra piece you install into an AI programming tool such as Claude Code. It is for people who already let an AI write code for them and want to see the plan first. Open source, one line to install.

02 / How it works

What it does, in plain words

Most AI coding tools start typing before they understand what they are looking at. That is how you get a fix for the wrong problem, or two helpers changing the same file at the same time.

It reads first.

Before anything is changed, it reads the project: what was done recently, what is open, what is broken. Then it says out loud what it found.

You agree the plan.

It proposes what to touch and what to leave alone. You say yes, or change it. Nothing starts before that.

The job is cut into five parts.

The work is split into five steps: read, build, polish, check, finish. Each step has its own helper and its own short list of files it may touch.

A check between every step.

After each step an automatic check runs. If it fails, the next step does not start. Asking nicely does not help. Skipping is not built in.

What stays when the session ends.

A written record of what was done and what was not, plus notes for next time. Nothing is learned silently.

04 / Install

Pick your tool

Same plugin, four install paths.

Claude Code

plugin marketplace

/plugin marketplace add Kanevry/session-orchestrator

/plugin install session-orchestrator@kanevry

Then run npm install once inside the plugin cache and restart Claude Code.

Known broken. The one-liner documented for this step until 2026-08-19 does not work: claude plugin dir is not a subcommand Claude Code has, so it exits 1 and the fallback path it then used does not exist. The replacement below resolves the path from the plugin cache instead, and was run end to end on a real install.

cd "$(dirname "$(find ~/.claude/plugins/cache -name package.json -path '*session-orchestrator*' | head -1)")" && npm install

Codex CLI

clone and installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/codex-install.mjs

Reads AGENTS.md instead of CLAUDE.md.

No scope enforcement. The file-scope hook does not run on this harness. The five passes and the quality gates work; the write boundary is a convention here, not a mechanism.

Cursor IDE

clone and installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/cursor-install.mjs /absolute/path/to/your/project

Path required. The project path is mandatory. Without it the installer reports success falsely.

Pi

package manager

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

pi install npm:session-orchestrator

This path installs its own dependencies; the other three need npm install once.

05 / For developers

Five passes, one gate between each

Write access is declared per wave, and the Quality gate cannot be skipped.

Five passes: who runs them, what they may write, how many files, and the gate that follows
PassWho runs itMay writeFilesGate after
W1 Discovery read-only explorers nothing 0 findings validated
W2 Impl-Core code, db, ui implementers core feature code 12 incremental gate
W3 Impl-Polish fix and integration agents bug fixes, edges 5 incremental gate
W4 Quality simplifiers, test-writer, read-only panel tests only 8 full gate, un-skippable
W5 Finalization 1 to 2 agents SSOT, issue cleanup 2 final review

File counts are the declared write scopes of one session, not a fixed quota. A wave declares its scope before it runs; the numbers change per session, the rule does not.

06 / Enforced

Every claim names the file that enforces it

A sentence in a prompt is a wish. These five are code paths.

Each claim and the file that enforces it
ClaimEnforced in
The write scope of an agent is fixed before it starts. scripts/validate-wave-scope.mjs --assert-disjoint
A write outside that scope is refused, not warned about. hooks/enforce-scope.mjs
Destructive shell commands are blocked by policy, not by prompt. .orchestrator/policy/blocked-commands.json, 14 rules

08 / Questions

Questions people ask

Is this itself an AI that writes code?

No. It is an add-on that organises how an AI coding tool works. The tool still writes the code; this decides what it reads first, what it may touch, and when it has to stop and be checked.

Which tools does it work with?

Claude Code fully. Codex CLI, Cursor IDE and Pi run it with limits: on Codex CLI the short list of files a step may touch is not enforced, on Cursor IDE it is checked after the work is done, and Pi runs through a bridge. The install section lists the path for each.

What is different from just using Claude Code?

Four things: the reading step before any change, a plan you agree to, a short list of files per step, and an automatic check between the steps. Without them the tool starts typing on the first sentence it reads.

Does it send data anywhere?

No account and no server. Everything runs on your own machine. Usage data is sent only if you switch it on, and it is off until you do. This website loads nothing from another site.

Does it work on Windows?

It runs natively on Windows, but Windows is not covered by the automated test runs. macOS and Linux are, so those two are the paths that get checked on every change.

What does it cost?

Nothing. It is free and open source under the MIT licence. You still pay whatever your coding tool costs; that part is not affected.

Can it break my project?

Commands that would delete or overwrite work are blocked by a policy file, not by a polite instruction. It never overwrites the shared history of your project. It records the changes at the end of a session, after the checks have run, and it tells you what it recorded.

Who maintains it?

One person, Bernhard Götzendorfer. Questions filed on GitHub are answered by him. It is shipped as-is, with best-effort maintenance and no service level agreement.

09 / Limits

What this is, and what it is not

  • Independent and community-maintained. Not affiliated with or endorsed by Anthropic, OpenAI, or Cursor.
  • Shipped as-is, with no service level agreement and best-effort maintenance.
  • Local by default. No account, no server. Telemetry is strictly opt-in.
  • macOS and Linux are fully supported and covered by CI. Windows runs natively but is not CI-covered.
  • There is no leaderboard and no overall score. Where a number is missing, it says so instead of guessing. A ranking built on a comparison method that is not yet honest would be worse than none.
  • Hook-level enforcement is not the same on every harness. The list below is the current state, not a roadmap. The quality gates are identical everywhere.
