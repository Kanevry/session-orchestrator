Why this exists

Most agentic-coding tools jump straight into writing code.

This one puts a loop around it: research, agree on scope, then execute in typed waves with gates.

Every session writes a record. Every unfinished item becomes a ticket. Every claim carries the command that proves it.

The loop

Three commands, four stages

The whole surface is three slash commands.

/session feature    # research, agree on scope
/go                 # five typed waves, gate between each
/close              # verify, commit, file the rest

  1. Stage 1 · Research

    /session

    Take stock first: what changed, what is open, what broke last time.

    Under the hood: session lock, CI banner, forced What Not To Retry read, mode recommendation with confidence.

  2. Stage 2 · Plan

    wave decomposition

    Work is split into five passes, each with a brief: which task, which files, what done means.

    Under the hood: file-scope deconfliction, so two agents never hold the same file.

  3. Stage 3 · Wave-execute

    /go

    Everyone reads before anyone writes. Core, then edges, then simplify and test, then wrap up.

    Under the hood: a typecheck, test and lint gate between waves, then review, then STATE.md.

  4. Stage 4 · Close

    /close

    Nothing is done because someone said so. Every planned item is checked against evidence.

    Under the hood: Full Gate, files staged individually, carryover tickets, learnings written down.

The five waves

Five typed passes with a gate between each

Write access is declared per wave. The Quality gate cannot be skipped.

Merge conflicts by construction

File-scope deconfliction means two agents never write the same file.

Context isolation

Each agent holds its own task and nothing of the others.

Guardrails, not vibes

Every guardrail names the file that enforces it

Each one is a hook, a lock, a policy file or a gate you can read.

Destructive-command guard

14 rules stop git reset, git clean, rm -rf, force-push and SQL DROP before the shell sees them.

hooks/pre-bash-destructive-guard.mjs

Scope enforcement

A PreToolUse hook blocks writes outside the paths an agent declared.

hooks/enforce-scope.mjs

Verification Iron Law

No completion claims without fresh verification evidence. "Should work now" is a banned phrase.

.claude/rules/verification-before-completion.md

Full Gate, un-skippable

Typecheck at 0, tests at exit 0, lint, plus a debug-artifact scan.

Session lock + heartbeat

A per-repo lease with an atomic claim, so a second session is detected, not guessed.

Subagent git ban

Subagents never run git add, commit, stash or push. Edit inside scope is their only channel.

Session types

Three sizes, one loop

The loop does not change, only how much machinery the work is worth.

housekeeping

Repo upkeep: drift check, stale branches, CI health.

Express path for up to 3 small tasks, no subagents.

feature

One shaped piece of work, all five waves, 4 to 6 agents per wave.

Issue premises are verified first, so a stale ticket does not consume a wave.

deep

Architecture refactors, audits, cross-cutting epics.

Up to 10 to 18 agents per wave, full review panel at Quality.

Memory

Nothing is learned silently

Every write is confirmed by the operator. Every artifact is plain text.

The record

Learnings carry a confidence score and an expiry: 0.5 at the start, +0.15 on confirmation, -0.2 on contradiction.

.orchestrator/metrics/

Rules are proposed, not applied

Reconcile proposes rules, the operator approves. An always-on rule is structurally impossible.

skills/reconcile/SKILL.md

What Not To Retry

Failed approaches are force-read at the next session start, so a dead end is not re-explored.

Across repositories

Built for one operator with many repos

Not team features. GitLab and GitHub both, auto-detected.

/portfolio

A read-only dashboard across every vault-registered repo: issues, merge requests, critical labels, stale signals.

/dispatcher

Ranks free repos on backlog, staleness and readiness, then claims the lease atomically.

Active-sessions board

A session that crashed in one repo shows up as force-closed from any other repo's session start.

Install

Pick your harness

Same plugin, four install paths. Copy the line, run it, then add one config block.

Prerequisite: Node.js >= 24. Package session-orchestrator on npm, v3.18.0, MIT.

Claude Code

full enforcement

Plugin marketplace install. The post-install step below is the most common reason an install looks broken.

  1. 1 · add the marketplace
    /plugin marketplace add Kanevry/session-orchestrator
  2. 2 · install the plugin
    /plugin install session-orchestrator@kanevry
  3. 3 · post-install, required
    cd "$(claude plugin dir session-orchestrator 2>/dev/null || echo ~/.claude/plugins/session-orchestrator)" && npm install
  4. 4 · finish

    Restart Claude Code. The plugin's hooks register at session start.

Codex CLI

AGENTS.md

Clone and run the installer. Codex reads AGENTS.md where Claude Code reads CLAUDE.md.

  1. 1 · clone and install
    git clone https://github.com/Kanevry/session-orchestrator.git ~/Projects/session-orchestrator && cd ~/Projects/session-orchestrator && npm install && node scripts/codex-install.mjs

  2. Scope enforcement is currently unavailable on this harness. Quality gates run in full.

Cursor IDE

per project

Same clone, then point the installer at your project.

  1. 1 · clone and install
    git clone https://github.com/Kanevry/session-orchestrator.git ~/Projects/session-orchestrator && cd ~/Projects/session-orchestrator && npm install
  2. 2 · wire a project
    node scripts/cursor-install.mjs /path/to/your/project

Pi

  1. 1 · install
    pi install npm:session-orchestrator

  2. Hook enforcement is bridged on this harness. Quality gates run in full.

Eval standard · aiat-llm-eval/1.0

An open spec defined by what it refuses

Three refusals rather than a score.

No global score

The validator rejects overall, total and mean. One number hides the dimension that went wrong.

Missing data abstains

An absent measurement returns cannot-determine, never a zero.

No superlatives

A conforming tool may not emit them.

Leaderboard

The record schema is ready. The site is deliberately not. A leaderboard published before the comparison method is honest would be the exact failure the spec exists to prevent.
