01 / What it is

It reads first, asks, then works in checked steps.

Session Orchestrator is a free extra piece you install into an AI programming tool such as Claude Code. It is for people who already let an AI write code for them and want to see the plan first. Open source, with installation steps for each tool.

02 / How it works

What it does, in plain words

An AI coding session can fix the wrong problem or send two helpers into the same file. This workflow starts with shared context and a declared scope before implementation.

It reads first.

Before anything is changed, it reads the project: what was done recently, what is open, what is broken. Then it says out loud what it found.

You agree the plan.

It proposes what to touch and what to leave alone. You say yes, or change it. Nothing starts before that.

The job is cut into five parts.

The work is split into five steps: read, build, polish, check, finish. Each step has its own helper and its own short list of files it may touch.

A check between every step.

Each step ends with a check appropriate to the work. The workflow stops on failure so the result can be corrected before the next step.

What stays when the session ends.

A written record of what was done and what was not, plus notes for next time. Nothing is learned silently.

04 / Install

Pick your tool

Same plugin, four install paths.

Claude Code

plugin marketplace

/plugin marketplace add Kanevry/session-orchestrator

/plugin install session-orchestrator@kanevry

Then run npm install once inside the plugin cache and restart Claude Code.

claude plugin list --json

Find the enabled session-orchestrator@kanevry entry. Replace the placeholder below with its installPath. If the entry is missing or disabled, resolve that through /plugin first. If several entries match, check the active installation instead of guessing.

cd "/absolute/installPath/from/the/list" && npm install

Codex CLI

clone and installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/codex-install.mjs

Requires Codex CLI 0.144.4 or later. Config goes in AGENTS.md. After installation, open a fresh task and review the plugin hooks through /hooks.

Select the Session Orchestrator skills: $session-orchestrator:bootstrap, then $session-orchestrator:session feature, $session-orchestrator:go, and $session-orchestrator:close. See the first-session guide.

No scope enforcement. The file-scope hook does not run on this harness. The five passes and the quality gates work; the write boundary is a convention here, not a mechanism.

Cursor IDE

clone and installer

git clone https://github.com/Kanevry/session-orchestrator.git

cd session-orchestrator && npm install

node scripts/cursor-install.mjs /absolute/path/to/your/project

Target project. Pass the target project explicitly. Without a path, the installer uses the current directory.

Pi

package manager

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

pi install npm:session-orchestrator

This path installs its own dependencies; the other three need npm install once.

05 / For developers

Five passes, one gate between each

Files are declared per wave. The workflow requires a full quality check before finalization.

Five passes: who runs them, what they may write, how many files, and the gate that follows
PassWho runs itMay writeFilesGate after
W1 Discovery read-only explorers nothing 0 findings validated
W2 Impl-Core code, db, ui implementers core feature code 12 incremental gate
W3 Impl-Polish fix and integration agents bug fixes, edges 5 incremental gate
W4 Quality simplifiers, test-writer, read-only panel simplification and tests 8 full quality gate
W5 Finalization 1 to 2 agents SSOT, issue cleanup 2 final review

File counts are the declared write scopes of one session, not a fixed quota. A wave declares its scope before it runs; the numbers change per session, the rule does not.

06 / Enforced

Checks and the rules behind them

Some protections run in code; others are instructions the agent must follow. Their strength depends on the tool and configuration.

Each check or workflow rule and its source
ClaimSource
The write scope of an agent is fixed before it starts. scripts/validate-wave-scope.mjs --assert-disjoint
On supported tools, strict mode blocks out-of-scope edits; warn mode reports them. hooks/enforce-scope.mjs
The destructive-command policy blocks 10 command patterns and warns on 4. .orchestrator/policy/blocked-commands.json, 14 rules
Subagents are instructed to leave staging and commits to the coordinator. This is a workflow rule. .claude/rules/parallel-sessions.md, PSA-007
The close workflow requires evidence for every planned item. skills/session-end/SKILL.md

08 / Questions

Questions people ask

Is this itself an AI that writes code?

No. It is an add-on that organises how an AI coding tool works. The tool still writes the code; this decides what it reads first, what it may touch, and when it has to stop and be checked.

Which tools does it work with?

Claude Code supports the full hook workflow. Codex CLI runs the workflows as selectable skills but cannot enforce file scope. Cursor bridges checks before tool and shell execution, with additional checks after edits. Pi uses a tool-call bridge. Parallel agents are available on Claude Code and Codex; Cursor and Pi run tasks sequentially.

What is different from just using Claude Code?

It adds a repeatable session workflow: read the project, agree the scope, divide the work into steps with declared files, and check the results between steps. The session record carries progress and unfinished work into the next session.

Does it send data anywhere?

The plugin runs locally without its own account. Optional usage telemetry is off until you consent. By default, session-start checks the npm registry for updates. Successful results are cached for 24 hours per repository; a failed request or cache write may cause another request at the next session. SO_DISABLE_UPDATE_CHECK=1 or DO_NOT_TRACK=1 disables the check. Your coding tool and configured services still use their own network connections. This website uses cookieless Vercel Web Analytics, described in its privacy policy.

Does it work on Windows?

macOS and Linux are covered by CI. Native Windows use has not been tested. The Node core uses portable paths, but the shell-based hooks and optional MCP server need WSL or Git Bash. Treat Windows support as best-effort.

What does it cost?

Nothing. It is free and open source under the MIT licence. You still pay whatever your coding tool costs; that part is not affected.

Can it break my project?

It can still make mistakes. The destructive-command policy has 14 rules: 10 block commands and 4 warn. File-scope protection depends on your coding tool and enforcement setting. Review changes and keep backups; the checks reduce risk, but do not guarantee correct code.

Who maintains it?

One person, Bernhard Götzendorfer. Questions filed on GitHub are answered by him. It is shipped as-is, with best-effort maintenance and no service level agreement.

09 / Limits

What this is, and what it is not

  • Independent and community-maintained. Not affiliated with or endorsed by Anthropic, OpenAI, or Cursor.
  • Shipped as-is, with no service level agreement and best-effort maintenance.
  • Local by default, without its own account. Optional telemetry is off; the npm update check can be disabled separately.
  • macOS and Linux are covered by CI. Native Windows use is untested; shell hooks and the optional MCP server need WSL or Git Bash.
  • There is no leaderboard and no overall score. Where a number is missing, it says so instead of guessing. A ranking built on a comparison method that is not yet honest would be worse than none.
  • Hook-level enforcement is not the same on every harness. The list below is the current state, not a roadmap. The configured quality checks run on all four tools.
