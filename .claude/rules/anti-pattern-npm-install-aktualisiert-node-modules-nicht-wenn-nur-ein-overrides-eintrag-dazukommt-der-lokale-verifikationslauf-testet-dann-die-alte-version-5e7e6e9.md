# Auto-generated rule: npm install aktualisiert node_modules nicht, wenn nur ein overrides-Eintrag dazukommt — der lokale Verifikationslauf testet dann die alte Version

Ein neuer overrides-Eintrag in package.json aendert das Lockfile, aber npm haelt den vorhandenen node_modules-Baum fuer aktuell (node_modules/.package-lock.json stimmt strukturell) und installiert NICHT neu. npm install --dry-run schlaegt entsprechend nichts vor. Jeder danach laufende lokale Test/Lint prueft die ALTE Version und meldet gruen — eine wertlose Verifikation, die wie eine echte aussieht. Der einzige belastbare lokale Beweis ist npm ci in einem Wegwerf-Verzeichnis mit exakt diesem Lockfile. Zweitbefund: npm audit fix behauptet bei transitiven Deps oft einen Fix und liefert im Dry-Run die Vulnerability unveraendert zurueck, wenn die gefixte Version ausserhalb des Semver-Ranges des Parents liegt — dort ist ein overrides-Eintrag der einzige Weg.
