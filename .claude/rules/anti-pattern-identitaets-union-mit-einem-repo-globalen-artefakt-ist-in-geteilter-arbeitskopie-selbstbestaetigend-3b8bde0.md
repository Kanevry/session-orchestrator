# Auto-generated rule: Identitaets-Union mit einem repo-globalen Artefakt ist in geteilter Arbeitskopie selbstbestaetigend

Wer 'bin ich das?' fragt, darf keine Quelle unionieren, die alle Sessions der Arbeitskopie teilen: session.lock haelt EINE Identitaet, also matchte das Manifest des Peers ueber dessen eigene Lock-Id und Gate 7 sperrte die zweite Session aus (#1194, exakt die #1082-Sperre, die G3b beenden sollte). Prozess-lokale Tiers ERSETZEN die geteilte Quelle, sie ergaenzen sie nicht (HR-102). Der Preis - ein Schreiber, der eine fremde Id in sein eigenes Manifest stempelt, entwaffnet den eigenen Guard - gehoert auf die Schreiberseite.
